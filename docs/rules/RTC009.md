# RTC009 - Known-vulnerable Polkadot crate version

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | on | syntax (reads `Cargo.lock`) | `known-vulnerable-crate-version` |

## What it finds

A `Cargo.lock` pins a Polkadot crate version that has a known security bug. The
fix shipped as a quiet patch release, with no RustSec or GHSA advisory.

## Why it matters

`cargo audit` and `cargo deny` do not report these bugs. A runtime keeps the
bug until its `Cargo.lock` gets the patch release and a runtime upgrade ships.

The October 2026 dotUSD exploit (about $1.38M) used such a bug. Master fixed it
in June 2026 ([#11910](https://github.com/paritytech/polkadot-sdk/pull/11910)).
Production runtimes kept `staging-xcm-executor 28.0.1` until fellows runtime
2.5.1 ([runtimes#1331](https://github.com/polkadot-fellows/runtimes/pull/1331))
in late October.

## Example

```toml
# Bad: dotUSD WithdrawAsset bug. The fix on this line is 28.1.0.
[[package]]
name = "staging-xcm-executor"
version = "28.0.1"
source = "registry+https://github.com/rust-lang/crates.io-index"
```

## How to fix

1. Update to the first fixed version on your release line, for example
   `cargo update -p staging-xcm-executor --precise 28.1.0`. You can also use
   psvm for a full SDK patch release.
2. Build the runtime again.
3. Ship it in a runtime upgrade.

## Affected versions

The list is in
[`src/rules/vulnerable_crates.tsv`](https://github.com/agustinustheo/polkadot-linter/blob/main/src/rules/vulnerable_crates.tsv).
Each row covers one release line. A version is affected from the first
vulnerable version up to the first fixed version on that line.

| Crate | Affected | First fixed | Advisory |
| --- | --- | --- | --- |
| `staging-xcm-executor` | 18.0.1-18.0.5, 21.0.0 | no fix on these lines | [InitiateTransfer origin leak](https://forum.polkadot.network/t/postmortem-xcm-initiatetransfer-origin-leak/17357) (Feb 2026) |
| `staging-xcm-executor` | 19.1.0-19.1.3, 20.0.0-20.0.1, 22.0.0, 23.0.0, 24.0.0 | 19.1.4, 20.0.2, 22.0.1, 23.0.1, 24.0.1 | same |
| `staging-xcm-executor` | 25.0.0-25.1.0, 26.0.0, 27.0.0, 28.0.0-28.0.1 | 25.2.0, no fix for 26, 27.1.0, 28.1.0 | dotUSD: `WithdrawAsset` imbalance escapes the rollback ([SEC019](SEC019.md)) |

29.0.0 has both fixes. Each boundary was checked in the published crate source.
If a line has no fix, the message names the nearest fixed release on a later
line.

## Limits

- It checks only crates.io packages. It skips path, git and private-registry
  packages, because their version number does not show the code. Forks such as
  the moonbeam or hydration SDK forks are not checked.
- It skips pre-release versions.
- It checks every `Cargo.lock` that the scan reaches, not only runtime crates.
  If you exclude `*.lock`, the rule does not run.
- The list is incomplete and current as of 2026-11. If RTC009 reports nothing,
  the lockfile can still be unsafe. Use `cargo audit` or `cargo deny` for
  generic crates.
- Allow comments do not work in `Cargo.lock`. Use a baseline to hide a finding.
- Evidence: polkadot-fellows/runtimes `66945c6265` (28.0.1) and `4e17c8e79`
  (23.0.0) fire. The fixed releases do not fire.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.

## Adding a row

Add a row only for a Polkadot-specific fix with no RustSec or GHSA entry. Check
the boundary in the published crate source. Cite the fix or the postmortem URL.
