# RTC005 - Insecure collective-flip randomness

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `insecure-randomness-in-runtime` |

## What it finds

A runtime pallet uses `pallet_insecure_randomness_collective_flip` (before the
rename: `pallet_randomness_collective_flip`) as its randomness source. It does
not report the pallet's declaration, or `pallet_contracts` (only the deprecated
`seal_random` uses it).

## Why it matters

This pallet makes its value from the hashes of the last 81 blocks. Anyone can
predict the value. A block author can change it by not producing a block. The
pallet is for tests only.

## Example

```rust
// Bad
impl pallet_contracts::Config for Runtime {
    type Randomness = RandomnessCollectiveFlip;
}
```

```rust
// Good
impl pallet_contracts::Config for Runtime {
    type Randomness = pallet_babe::RandomnessFromOneEpochAgo<Runtime>;
}
```

## How to fix

1. Use BABE randomness on a relay chain or solochain.
2. On a parachain, use relay-chain VRF output, not local block hashes.
3. Remove the pallet from `construct_runtime!`.

## Limits

- It reports `construct_runtime!` entries and types that name the pallet or
  `RandomnessCollectiveFlip`.
- It skips entries behind `#[cfg(test)]`, `runtime-benchmarks`, `try-runtime`
  or `test-helpers`.
- It skips `use` items, the empty `impl Config`, comments, and storage prefixes
  in removal migrations.
- Pinned SDK: 0 production findings. A test fixture guards recall.

Runtime scope: see [Runtime configuration rules](runtime-config.md).

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
