# TST004 - Missing Pays::Yes Error-Path Test for Fee-Refunding Extrinsics

> **Severity:** Advisory · **Family:** test-smell · **Engine:** source analysis (syn) · **Rule name:** `pays-yes-error-path`

## Description

Extrinsics that return `Pays::No` on success refund the caller's transaction fee. This is a common pattern for calls the chain wants to subsidise — claiming, reporting misbehaviour, oracle submissions. The pattern is only safe if the *error* path still charges `Pays::Yes`: the fee is the chain's spam defence, and a call that is free even when it fails can be submitted in unlimited volume at zero cost. An attacker can flood blocks with deliberately failing calls, consuming block weight and squeezing out paying transactions — a fee-less denial-of-service vector.

Whether the error path charges fees is easy to get wrong. Returning early with a plain `Err(...)` inherits the declared dispatch info, and a refactor that moves the `Pays::No` from the return value into the `#[pallet::weight]` declaration can silently make failures free. The only durable guard is a test that dispatches the failing case and asserts that `pays_fee` on the resulting `PostDispatchInfo` is `Pays::Yes`.

This rule enforces the presence of that companion test: production code that refunds fees on success must be accompanied by a test proving the error path still pays.

The rule authority matrix (`docs/rule-authority-matrix.md`) keeps TST004 on source analysis: it reasons about a *missing* companion error-path test across files, a cross-test semantic-intent comparison the compiler cannot yet make.

## What it detects

In non-test Rust files (files under `tests/`, or ending in `tests.rs` / `_test.rs` / `_tests.rs`, are skipped):

- an `Ok(...)` expression whose argument contains `Pays::No` (i.e. a dispatchable success path that refunds the fee), **and**
- no companion test file (`tests.rs` or any `.rs` file in a sibling `tests/` directory) that contains both `pays_fee` and `Pays::Yes` — the signature of an error-path fee assertion.

Each `Ok(... Pays::No ...)` site is flagged when the companion assertion is absent.

## What should be avoided

```rust
#[pallet::call_index(0)]
#[pallet::weight(T::WeightInfo::claim())]
pub fn claim(origin: OriginFor<T>) -> DispatchResultWithPostInfo {
    let who = ensure_signed(origin)?;
    ensure!(Claims::<T>::contains_key(&who), Error::<T>::NothingToClaim);
    // ...
    Ok(Pays::No.into()) // ❌ refunds fees, but no test proves failures still pay
}
```

Without an error-path fee test, nothing stops a later change from making the `NothingToClaim` failure free as well — turning `claim` into an unlimited free-spam call.

## Best practice

```rust
// tests.rs
#[test]
fn failed_claim_still_pays_fees() {
    new_test_ext().execute_with(|| {
        let result = Pallet::<Test>::claim(RuntimeOrigin::signed(NO_CLAIM_ACCOUNT));
        let post_info = result.unwrap_err().post_info;
        assert_eq!(post_info.pays_fee, Pays::Yes); // ✅ error path charges fees
    });
}
```

The test pins the anti-spam property: only successful claims are subsidised, failures always cost the caller.
