# SEC011 - Unbounded storage iteration in a callable path

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | compiler (needs the driver) | `storage-iteration-in-dispatchables` |

## What it finds

Code that a dispatchable or a hook can reach calls `iter()` or `drain()` on a
storage map, with no fixed limit.

## Why it matters

Each key is one database read. Users control the number of keys, so the cost
increases with the state. The declared weight usually does not increase. A
large map can make a call or a hook go over the block limit or the PoV limit.
A hook in `on_initialize` runs this cost in every block.

## Example

```rust
// Bad: reads every key in the map.
for (id, deadline) in Listings::<T>::iter() {
    if deadline < now {
        Listings::<T>::remove(id);
    }
}

// Good: reads at most 50 keys per call.
const MAX_PURGE_PER_CALL: usize = 50;
for (id, deadline) in Listings::<T>::iter().take(MAX_PURGE_PER_CALL) {
    if deadline < now {
        Listings::<T>::remove(id);
    }
}
```

## How to fix

Do one of these:

- Process a fixed number of entries per call or per block. Continue from a
  cursor.
- Measure the work with a `WeightMeter`.
- Use a bounded type, such as `BoundedBTreeMap<_, _, T::MaxListings>`.
- Keep an aggregate value up to date on each write, so you do not iterate.

## How it decides

- It checks `StorageMap`, `CountedStorageMap`, `StorageDoubleMap` and
  `StorageNMap`.
- It follows the local call graph from public functions and FRAME entry
  points, so it finds iteration in private helpers.
- `.take(n)` stops a finding when `n` is a literal, or a local that holds a
  literal on every path.
- It skips code reached only from upgrade hooks, `try_state` or
  `#[cfg(feature = "try-runtime")]`. A function name such as `migrate_*` does
  not cause a skip. SEC012 still checks these paths.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
