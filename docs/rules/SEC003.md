# SEC003 - Decoding Recursive Runtime Types Without a Depth Limit

> **Severity:** Warning · **Family:** security · **Engine:** compiler-backed (rustc driver) · **Rule name:** `missing-decode-depth-limit`

## Description

Some runtime types are recursive by construction. `RuntimeCall` is the canonical example: `utility.batch` takes a `Vec<RuntimeCall>`, each of which may itself be a `batch`, a `proxy.proxy`, a `sudo.sudo`, and so on. The same applies to `UncheckedExtrinsic` and `OpaqueExtrinsic`, which wrap a call. SCALE decoding of such a type is itself recursive: every nesting level adds a stack frame.

If a pallet decodes attacker-controlled bytes into one of these types with a plain `Decode::decode()`, an adversary can submit a payload shaped like `batch(batch(batch(...)))` thousands of levels deep. The decoder recurses until the Wasm stack is exhausted, and a stack overflow inside the runtime is a trap — block production or block import aborts. Because the malicious payload is small on the wire (each nesting level costs only a few bytes), this is a cheap denial-of-service attack.

The codec crate provides the antidote: `DecodeLimit::decode_with_depth_limit` and `decode_all_with_depth_limit` fail gracefully with a decoding error once the nesting budget (conventionally `sp_api::MAX_EXTRINSIC_DEPTH`) is exceeded. FRAME itself uses depth-limited decoding wherever call data crosses a trust boundary — for example when a preimage or a remark is turned back into a `RuntimeCall`.

## What it detects

The rustc driver performs a taint analysis starting from runtime entry-point parameters (data an external caller controls) and reports a `decode` call when all of the following hold:

- the call is an unlimited `decode` (a `Decode::decode(...)` path call or a `.decode()` method call — not `decode_with_depth_limit`/`decode_all_with_depth_limit`);
- the decoded type (or the decode receiver) resolves to, or contains, a recursive decode target: `RuntimeCall`, `UncheckedExtrinsic`, or `OpaqueExtrinsic` — including when nested inside other generic types, aliases, tuples, or self-referential ADTs;
- the input being decoded is tainted, i.e. derived from an entry-point parameter (the taint tracking follows assignments, field/index projections, match arms, and `using_encoded` closures).

The diagnostic message is "Recursive runtime type is decoded without a depth limit".

## What should be avoided

```rust
#[pallet::call_index(3)]
#[pallet::weight(T::WeightInfo::execute())]
pub fn execute(origin: OriginFor<T>, encoded: Vec<u8>) -> DispatchResult {
    ensure_signed(origin)?;
    let call = <T as Config>::RuntimeCall::decode(&mut &encoded[..])
        .map_err(|_| Error::<T>::InvalidCall)?;
    call.dispatch(frame_system::RawOrigin::Signed(who).into())
        .map(|_| ())
        .map_err(|e| e.error)
}
```

`encoded` is fully attacker-controlled; a deeply nested `batch` payload overflows the decoder's stack before `InvalidCall` is ever returned.

## Best practice

```rust
use codec::DecodeLimit;

pub fn execute(origin: OriginFor<T>, encoded: Vec<u8>) -> DispatchResult {
    ensure_signed(origin)?;
    let call = <T as Config>::RuntimeCall::decode_with_depth_limit(
        sp_api::MAX_EXTRINSIC_DEPTH,
        &mut &encoded[..],
    )
    .map_err(|_| Error::<T>::InvalidCall)?;
    // ...
}
```

Over-nested payloads now fail with an ordinary decode error instead of exhausting the stack; `decode_all_with_depth_limit` additionally rejects trailing bytes.
