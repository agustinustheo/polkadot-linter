# SEC024 - Discarded funds in an error

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | off | compiler (needs the driver) | `discarded-funds-in-error` |

## What it finds

Code drops a `Result` whose `Err` holds funds, such as the `Result` from
`resolve` or `settle`.

## Why it matters

`fungible::Balanced::resolve(who, credit)` returns the credit in `Err` when the
deposit fails. For example, the account is below the existential deposit,
frozen, or does not exist. If the code drops the `Result`, the `Credit` is
dropped and burns issuance. Nothing reports it. `settle` returns a `Debt` in
`Err` in the same way, and a dropped `Debt` mints.

## Example

```rust
// Bad: the credit burns if `pot` cannot receive it.
let _ = T::Currency::resolve(&pot, credit);
T::Currency::resolve(&pot, credit).ok();

// Good: send the credit to a handler.
if let Err(credit) = T::Currency::resolve(&pot, credit) {
    T::OnUnbalanced::on_unbalanced(credit);
}

// Good: the burn is intended and explicit.
let _ = T::Currency::resolve(&pot, credit).map_err(drop);
let _ = T::Currency::resolve(&pot, credit).defensive();
```

## How to fix

Handle the `Err` value. If you intend to burn the funds, write
`.map_err(drop)` or `.defensive()`.

## How it decides

- The `Err` type holds `Credit`, `Debt`, `NegativeImbalance`,
  `PositiveImbalance` or `AssetsInHolding`, also as a generic argument. These
  are the types that [SEC019](SEC019.md) tracks. A reference does not count.
- Dropped means: a statement, `let _ =`, or an unused `_`-prefixed name. This
  also applies after `.ok()`, `.err()`, `.map(..)`, `.is_ok()` or `.is_err()`.
- The rule checks closure bodies. It skips test and benchmark code, as
  [SEC022](SEC022.md) does.
- Not reported: `?`, `match`, `if let Err(..)`, `.map_err(..)`,
  `.inspect_err(..)`, `.unwrap_or_else(..)`, `.defensive()`, a condition, a
  binding used later, a returned `Result`, and funds only in `Ok`.

## Limits

Off by default. Most findings are correct, but the burn is intended. Measured
in November 2026 with `config/all-rules.toml`:

- polkadot-sdk `b18fb34`, 28 crates: 8 findings. 1 needs a fix:
  `polkadot/runtime/common/src/impls.rs:42` (`ToAuthor` burns the fee share if
  the author cannot receive it). 7 are commented as intended burns, for example
  in `xcm-executor`, `delegated-staking`, `staking` and `asset-tx-payment`.
- Astar `02b78d7`, `astar-runtime`: 2 findings, both need a fix
  (`runtime/astar/src/lib.rs:484` and `:638`, labels C012 and C006 in
  [the run audit](https://github.com/agustinustheo/polkadot-linter/blob/main/benchmarks/precision/2026-11-run-audit/labels.tsv)).
- Total: 10 findings, 3 need a fix, 7 are intended, 0 are false.

No upstream fix PR exists for this pattern. Use the rule to audit runtime
`OnUnbalanced` and `HandleCredit` handlers.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
To enable the rule, set `SEC024 = true` under `[rules.enabled]`.
