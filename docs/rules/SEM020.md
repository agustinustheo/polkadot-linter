# SEM020 - Precompile acts for the caller under delegatecall

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `precompile-without-delegate-guard` |

## What it finds

The `call` of a pallet-revive `impl Precompile` (it has an `env` parameter), in
a file that reads `.caller()` and has no delegate-call guard.

## Why it matters

Under DELEGATECALL, `env.caller()` is the original caller. An intermediate
contract can then act as that caller: move their assets or send XCM for them.
This occurred 3 times in one year:
[polkadot-sdk#11676](https://github.com/paritytech/polkadot-sdk/pull/11676)
(ERC20 assets precompile),
[polkadot-sdk#11715](https://github.com/paritytech/polkadot-sdk/pull/11715)
(XCM and asset-conversion precompiles) and individuality-community 68cab75
(personhood precompile).

## How to fix

Reject a delegate call at the start of `call`:

```rust
if env.is_delegate_call() {
    return Err(Error::Error(PrecompileDelegateDenied.into()));
}
```

## Limits

- Any `delegate` text in the file counts as a guard, for example
  `is_delegate_call()` in a helper or `ensure_not_delegate(env)?`.
- Frontier-style precompiles (`fn execute(handle)`) do not match.
- A precompile that does not read `.caller()` is not reported, for example the
  personhood precompile before 68cab75.
- Measured: 1 finding before #11676 and 1 before #11715 (XCM), 0 after. 0 on
  current polkadot-sdk and individuality-community.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
