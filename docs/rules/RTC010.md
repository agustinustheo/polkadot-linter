# RTC010 - Storage-reading aliaser on the unpaid-execution barrier

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `storage-reading-unpaid-aliaser` |

## What it finds

`AllowExplicitUnpaidExecutionFrom<_, A>` gets `pallet_xcm::AuthorizedAliasers`
as its aliaser filter `A`, directly or inside a tuple.

## Why it matters

The barrier checks the aliaser for each `AliasOrigin` before `UnpaidExecution`,
up to 5 times per message. Barriers run before the message pays any fee.
`AuthorizedAliasers` reads storage on keys that the message chooses. So any
incoming message can cause several storage reads that nobody pays for.

[polkadot-sdk#12831](https://github.com/paritytech/polkadot-sdk/pull/12831)
changed the barrier docs: pass only a cheap subset.
[fellows runtimes #1237](https://github.com/polkadot-fellows/runtimes/pull/1237)
fixed 11 system parachains.

## Example

```rust
// Bad
pub type TrustedAliasers = (AliasChildLocation, AuthorizedAliasers<Runtime>);
AllowExplicitUnpaidExecutionFrom<(ParentOrParentsPlurality, FellowshipEntities), TrustedAliasers>,
```

```rust
// Good
pub type CheapTrustedAliasers = (AliasChildLocation,);
pub type TrustedAliasers = (CheapTrustedAliasers, AuthorizedAliasers<Runtime>);
AllowExplicitUnpaidExecutionFrom<(ParentOrParentsPlurality, FellowshipEntities), CheapTrustedAliasers>,
```

## How to fix

1. Make a computation-only aliaser type for the barrier.
2. Keep `AuthorizedAliasers` only in the executor's `type Aliasers`.

## Limits

- It resolves same-file `type` aliases, also nested ones.
- It does not report the executor's `type Aliasers`. The executor runs after
  fees are paid.
- It knows only `AuthorizedAliasers`. It does not see a custom `ContainsPair`
  that reads storage.
- Evidence: 11 findings on the parent of #1237, exactly the 11 files that #1237
  changed. 0 after the merge and on polkadot-sdk master.

Runtime scope: see [Runtime configuration rules](runtime-config.md).

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.

## References

- polkadot-sdk [#12831](https://github.com/paritytech/polkadot-sdk/pull/12831): do not use expensive aliasers in `ExplicitUnpaidExecutionFrom`
- polkadot-fellows/runtimes [#1237](https://github.com/polkadot-fellows/runtimes/pull/1237): do not pass `AuthorizedAliasers` to the unpaid barrier
