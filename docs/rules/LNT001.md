# LNT001 - Invalid allow comment

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning or advisory | on | syntax | `allow-comment` |

## What it finds

A `// polkadot-linter: allow(..)` comment that is not correct, or that
suppresses nothing.

## Why it matters

An allow comment hides a finding. A bad allow comment hides nothing, so the
finding stays. An unused allow comment stays in the code after the code changes.

## Example

```rust
// Bad: no reason. This comment suppresses nothing.
// polkadot-linter: allow(RTC004)
type ExistentialDeposit = ConstU128<0>;
```

```rust
// Good:
// polkadot-linter: allow(RTC004, reason = "dev chain: accounts are free")
type ExistentialDeposit = ConstU128<0>;
```

## How to fix

- Give a non-empty `reason = "..."`.
- Use only rule IDs that exist.
- Remove an allow comment when it covers no finding.

## How it decides

| Problem | Severity |
| --- | --- |
| The comment cannot be parsed. | warning |
| The comment has no `reason`, or an empty one. | warning |
| The comment names an unknown rule. | warning |
| The comment covers no finding ("unused allow"). | advisory |

The rule checks an allow for "unused" only when its rule ran. With
`--syntax-only` or `--rules`, an allow for a rule that did not run is not
reported.

## Configuration

Set `LNT001 = false` under `[rules.enabled]` to turn the checks off. See
[Suppressing findings](../guide/suppressing-findings.md).
