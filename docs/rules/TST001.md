# TST001 - Prefer assert_noop! for Dispatch Error Assertions

> **Severity:** Warning · **Family:** test-smell · **Engine:** source analysis (syn) · **Rule name:** `prefer-assert-noop`

## Description

When a dispatchable call fails, FRAME's transactional layer must roll back every storage write the call made before hitting the error. A test that only checks "the call returned an error" proves half the contract: it confirms the error surfaced, but says nothing about whether storage was left untouched. On a live chain, a partially-applied failed extrinsic is a serious bug class — balances can be debited without the corresponding credit, counters can drift, and reserved funds can leak — precisely the situations the Libro guidance "Implement Tests for All Error Cases" warns about: untested error paths lead to unhandled scenarios and unpredictable behaviour.

The manual pattern of calling the dispatchable, asserting `.is_err()`, and then re-invoking or unwrapping with `.unwrap_err()` to inspect the error is both noisier and weaker than the purpose-built `assert_noop!` macro. `assert_noop!` executes the call inside a transactional layer, asserts the expected `DispatchError`, and additionally asserts that the storage root did not change — i.e. that the failed call really was a no-op.

Using `assert_noop!` consistently means every error-case test doubles as a storage-rollback regression test at zero extra cost.

## What it detects

In test files, within a single function body:

- an `assert!(...)` statement macro whose arguments contain `.is_err()`, followed within the next 4 lines by a `.unwrap_err()` method call;
- the same `is_err()` / `unwrap_err()` proximity pattern detected textually line-by-line, as a fallback for code the AST walk cannot attribute (e.g. inside other macro bodies).

Duplicate findings from the two passes on the same line are deduplicated.

## What should be avoided

```rust
#[test]
fn transfer_fails_when_frozen() {
    new_test_ext().execute_with(|| {
        assert!(Pallet::<Test>::transfer(RuntimeOrigin::signed(1), 2, 100).is_err());
        let err = Pallet::<Test>::transfer(RuntimeOrigin::signed(1), 2, 100).unwrap_err();
        assert_eq!(err, Error::<Test>::Frozen.into());
    });
}
```

The call is executed twice, the assertion is verbose, and nothing checks that the failed transfer left balances unchanged.

## Best practice

```rust
#[test]
fn transfer_fails_when_frozen() {
    new_test_ext().execute_with(|| {
        assert_noop!(
            Pallet::<Test>::transfer(RuntimeOrigin::signed(1), 2, 100),
            Error::<Test>::Frozen
        );
    });
}
```

One macro call asserts both the exact error and that storage was not modified by the failed dispatch.
