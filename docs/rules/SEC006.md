# SEC006 - Unchecked repatriate_reserved remainder

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | compiler (needs the driver) | `unchecked-repatriate-reserved` |

## What it finds

A call to `ReservableCurrency::repatriate_reserved` whose returned remainder is
not checked.

## Why it matters

`repatriate_reserved` moves as much as it can. `Ok(remaining)` is the amount
that it did **not** move. If the code ignores `remaining`, the pallet records
funds that it did not receive. Tests often miss this, because the reserve is
usually large enough.

## Example

```rust
// Bad: `?` unwraps `Ok(remaining)` and drops it.
T::Currency::repatriate_reserved(payer, treasury, fee, BalanceStatus::Free)?;
TotalCollected::<T>::mutate(|total| *total = total.saturating_add(fee));

// Good: record only the amount that moved.
let remaining =
    T::Currency::repatriate_reserved(payer, treasury, fee, BalanceStatus::Free)?;
let collected = fee.saturating_sub(remaining);
TotalCollected::<T>::mutate(|total| *total = total.saturating_add(collected));
```

## How to fix

Bind the remainder and use it. Do one of these:

- Subtract it from the amount that you record.
- Require full payment: `ensure!(remaining.is_zero(), Error::<T>::InsufficientReserve);`.

## How it decides

The rule reports a call in these cases:

- The call is a statement, so the result is dropped. This includes `...?;`.
- The result is bound to `let _ =`.
- The result is bound to a variable, but no later code checks it. A check is
  `is_zero`, `checked_sub`, `saturating_sub`, `defensive_saturating_sub`, a
  comparison or an arithmetic expression.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
