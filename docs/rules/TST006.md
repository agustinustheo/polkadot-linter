# TST006 - Storage-Mutating Extrinsic Without an Event

> **Severity:** Warning · **Family:** test-smell · **Engine:** source analysis (syn) · **Rule name:** `extrinsic-without-event`

## Description

Events are the runtime's outbound communication channel. Wallets, block explorers, indexers, bridges, and other pallets do not re-execute your extrinsic logic — they watch the event stream to learn what happened on chain. When a dispatchable mutates storage but emits no event, that state change is invisible off-chain: a UI cannot confirm the action to the user, an indexer cannot update its view, and post-incident forensics have to reconstruct state transitions by diffing storage across blocks.

This matters most for value-bearing operations. A transfer, registration, or parameter change that leaves no event forces every downstream consumer to poll storage, which is expensive, racy, and easy to get wrong. Libro's related guidance on event documentation makes the same point from the other direction: events are part of the runtime's public metadata contract with frontends, so they need to exist and be well described.

The convention this rule enforces is simple: if a `#[pallet::call]` dispatchable writes to storage, it should deposit at least one event describing the change.

The rule authority matrix (`docs/rule-authority-matrix.md`) records TST006's target authority as the rustc bridge, which uses compiler-resolved storage writes and authored event calls (validated against a pinned `pallet-timestamp` baseline). The syn implementation documented here detects the same authored pattern.

## What it detects

In non-test, non-benchmark Rust files:

- a function inside an `impl` block annotated `#[pallet::call]`, itself annotated `#[pallet::call_index]`, whose body
  - contains a storage mutation — a call or method call named `put`, `insert`, `mutate`, `remove`, `kill`, `set`, `append`, or `try_append` — and
  - contains no `deposit_event` call, and
  - does not always call a same-named function of the file's own non-test `impl Pallet<T>` blocks that contains one directly (not inside a closure or nested function). Only a call as a whole top-level statement, `let` initializer or tail (`Self::helper(..)?`, `Pallet::<T>::helper(..).map(..)`) counts; a call inside an `if`, `match`, loop, closure or `Ok(..)`, or a function value, does not. Only one level of helpers is followed.

## Not reported

- A privileged single setter: the first origin check (the first `ensure_*` call in the body) is `ensure_root(..)`, `T::X::ensure_origin(..)` with one argument, `ensure_origin_or_root(..)` or `ensure_admin*(..)`, written as a standalone statement `check(origin)?;` whose result is discarded. A bound result (`let who = T::X::ensure_origin(origin)?;`) is an account and is not privileged; neither is a fallback such as `if ensure_root(origin.clone()).is_err() { ensure_signed(origin)?; }`, a two-argument `EnsureOriginWithArg` check, `ensure_signed*` or `ensure_none`. The body must also have exactly one mutation call. Governance dispatches are observable through the Sudo, Scheduler or Referenda events that carry them. Signed and unsigned setters, and privileged calls with more than one mutation, are still reported. A single mutation inside a loop counts as one.
- Transient storage: the same storage item is both `set`/`put` and `kill`ed in one body (`dispatch_with_extra_gas`).
- Crates under a `test-runtime` or `tests` directory of their workspace. Example and template crates are still analyzed.

## What should be avoided

```rust
#[pallet::call_index(0)]
#[pallet::weight(T::WeightInfo::set_threshold())]
pub fn set_threshold(origin: OriginFor<T>, new: u32) -> DispatchResult {
    ensure_root(origin)?;
    Threshold::<T>::put(new); // ❌ state changes, but nothing is emitted
    Ok(())
}
```

The threshold silently changes; no wallet, indexer, or monitoring system can observe that it happened or what the new value is.

## Best practice

```rust
#[pallet::call_index(0)]
#[pallet::weight(T::WeightInfo::set_threshold())]
pub fn set_threshold(origin: OriginFor<T>, new: u32) -> DispatchResult {
    ensure_root(origin)?;
    let old = Threshold::<T>::get();
    Threshold::<T>::put(new);
    Self::deposit_event(Event::ThresholdUpdated { old, new }); // ✅ observable
    Ok(())
}
```

The event makes the state change observable off-chain and self-describing, including the values needed to act on it.

## Known limitations

Helpers are matched by name within the file. If one file holds several pallets, a same-named emitting helper of a sibling pallet's `impl Pallet<T>` can suppress a finding.
