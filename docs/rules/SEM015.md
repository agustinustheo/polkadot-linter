# SEM015 - Missing weight_of_authorize on an authorized call

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `missing-weight-of-authorize` |

## What it finds

A call has `#[pallet::authorize(..)]` but no
`#[pallet::weight_of_authorize(..)]`.

## Why it matters

The authorize closure runs during transaction pool validation, for every
candidate transaction. Without `weight_of_authorize`, nothing declares or
benchmarks that cost. An attacker can then send transactions that are cheap to
submit and costly to validate.

## Example

```rust
// Bad: the authorize path has no weight.
#[pallet::authorize(|_source, proof| Pallet::<T>::check_proof(proof))]
#[pallet::weight(T::WeightInfo::apply_update())]
pub fn apply_update(origin: OriginFor<T>, proof: T::Proof) -> DispatchResult {
```

```rust
// Good:
#[pallet::authorize(|_source, proof| Pallet::<T>::check_proof(proof))]
#[pallet::weight_of_authorize(T::WeightInfo::authorize_apply_update())]
#[pallet::weight(T::WeightInfo::apply_update())]
pub fn apply_update(origin: OriginFor<T>, proof: T::Proof) -> DispatchResult {
```

## How to fix

1. Benchmark the authorize closure.
2. Add `#[pallet::weight_of_authorize(..)]` with the generated weight.

## Limits

The rule skips test files and `#[cfg(test)]` modules.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
