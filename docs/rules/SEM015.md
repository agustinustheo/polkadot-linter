# SEM015 - Missing `#[pallet::weight_of_authorize]` on Authorized Calls

> **Severity:** Warning · **Family:** semantic · **Engine:** source analysis (syn) · **Rule name:** `missing-weight-of-authorize`

## Description

The `#[pallet::authorize(...)]` attribute lets a call declare its own authorization logic — a closure that runs during transaction validation, before the transaction is included in a block and before any fee-paying account is established. This is the general-transaction successor to `validate_unsigned`: the authorize closure typically reads storage, verifies signatures or proofs, and decides whether the pool should accept the transaction at all.

That validation work is not free, and it runs at a uniquely dangerous point: for every candidate transaction the pool sees, including spam that will never be included. FRAME therefore expects a companion `#[pallet::weight_of_authorize(...)]` attribute that benchmarks the authorize path *separately* from the call's execution weight. Without it, the cost of the authorization step is unaccounted for: the declared validation cost can silently drift away from the real work the closure performs, and an attacker who finds a cheap-to-submit, expensive-to-validate transaction gets free computation from every validating node.

Keeping a dedicated, benchmarked weight on the authorize path makes the validation cost explicit, keeps it in sync with the closure via the normal `WeightInfo` benchmarking workflow, and preserves the economic defenses that transaction weighing is supposed to provide.

## What it detects

- A function (free function or `impl` method, i.e. a pallet call) annotated with `#[pallet::authorize(...)]` that does not also carry a `#[pallet::weight_of_authorize(...)]` attribute.
- Test files and `#[cfg(test)]` modules are skipped.

## What should be avoided

```rust
#[pallet::call]
impl<T: Config> Pallet<T> {
    // ❌ authorize closure has no dedicated weight
    #[pallet::call_index(0)]
    #[pallet::authorize(|_source, proof| Pallet::<T>::check_proof(proof))]
    #[pallet::weight(T::WeightInfo::apply_update())]
    pub fn apply_update(origin: OriginFor<T>, proof: T::Proof, data: UpdateOf<T>) -> DispatchResult {
        ensure_authorized(origin)?;
        Self::do_apply(data)
    }
}
```

`check_proof` runs during pool validation for every candidate transaction, but its cost is never declared or benchmarked, so nodes perform unmetered work before any inclusion or fee decision.

## Best practice

```rust
#[pallet::call]
impl<T: Config> Pallet<T> {
    // ✅ validation and execution are weighed independently
    #[pallet::call_index(0)]
    #[pallet::authorize(|_source, proof| Pallet::<T>::check_proof(proof))]
    #[pallet::weight_of_authorize(T::WeightInfo::authorize_apply_update())]
    #[pallet::weight(T::WeightInfo::apply_update())]
    pub fn apply_update(origin: OriginFor<T>, proof: T::Proof, data: UpdateOf<T>) -> DispatchResult {
        ensure_authorized(origin)?;
        Self::do_apply(data)
    }
}
```

The authorize path now has its own `WeightInfo` entry, so a benchmark keeps the declared validation cost aligned with what `check_proof` actually does.
