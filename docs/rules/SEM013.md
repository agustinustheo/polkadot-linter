# SEM013 - Custom Invalidity Enum Without `#[repr(u8)]`

> **Severity:** Warning · **Family:** semantic · **Engine:** source analysis (syn) · **Rule name:** `custom-invalidity-repr-u8`

## Description

When a pallet rejects a transaction during validation — in `validate_unsigned`, a `SignedExtension`/transaction extension, or an `#[pallet::authorize]` closure — it typically returns `InvalidTransaction::Custom(u8)`. The single byte is all that leaves the runtime: it is what shows up in node logs, RPC error responses, and block-author telemetry. To keep these codes readable, pallets commonly define an enum such as `CustomInvalidity` with one variant per rejection reason and cast it with `e as u8`.

That cast relies on the enum's discriminant values. Without an explicit `#[repr(u8)]`, the representation is left to the Rust default (`repr(Rust)`), which makes the layout an implementation detail: the mapping from variant to byte is implicit rather than a declared contract. Anyone debugging a rejected transaction from the raw error code — or checking compatibility across runtime versions, where a reordered or inserted variant silently renumbers every subsequent code — has weaker guarantees to reason from.

Declaring `#[repr(u8)]` makes the discriminant layout explicit and self-documenting: the enum visibly *is* the byte protocol used on the wire, reviewers can see that each variant fits in a `u8`, and pairing it with explicit discriminants (`= 0`, `= 1`, …) freezes the code assignment against refactors.

## What it detects

- An `enum` whose name is `CustomInvalidity`, `CustomValidity`, or contains `Invalidity`, declared without a `#[repr(u8)]` attribute.
- Test files and `#[cfg(test)]` modules are skipped.

## What should be avoided

```rust
// ❌ implicit representation; the `as u8` mapping is an accident of layout
pub enum CustomInvalidity {
    StaleObservation,
    UnknownValidator,
    DuplicateSubmission,
}

impl From<CustomInvalidity> for TransactionValidityError {
    fn from(e: CustomInvalidity) -> Self {
        TransactionValidityError::Invalid(InvalidTransaction::Custom(e as u8))
    }
}
```

The byte emitted for each rejection reason is implicit, and reordering variants in a later release silently changes every error code that operators and downstream tooling have learned to interpret.

## Best practice

```rust
// ✅ explicit u8 representation and pinned discriminants
#[repr(u8)]
pub enum CustomInvalidity {
    StaleObservation = 0,
    UnknownValidator = 1,
    DuplicateSubmission = 2,
}

impl From<CustomInvalidity> for TransactionValidityError {
    fn from(e: CustomInvalidity) -> Self {
        TransactionValidityError::Invalid(InvalidTransaction::Custom(e as u8))
    }
}
```

The enum now declares its own wire format: each variant is provably a stable `u8`, and the error codes survive refactoring.
