# SEM011 - Zero weight in a weight attribute

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `weight-zero-placeholder` |

## What it finds

A `#[pallet::weight(..)]` or `#[pallet::weight_of_authorize(..)]` attribute
whose value is zero: `Weight::zero()`, `0`, or `Weight::from_parts(0, 0)`
(also `from_all` and `from_ref_time` with zero arguments).

## Why it matters

A zero weight makes the call free for block building and fees. An attacker can
fill blocks with free calls. Blocks then take too long or exceed the proof size
limit.

## Example

```rust
// Bad: the call reads and writes storage but costs nothing.
#[pallet::weight(Weight::zero())]
pub fn register(origin: OriginFor<T>, name: BoundedVec<u8, T::MaxNameLen>) -> DispatchResult {
```

```rust
// Good: the weight comes from a benchmark.
#[pallet::weight(T::WeightInfo::register())]
pub fn register(origin: OriginFor<T>, name: BoundedVec<u8, T::MaxNameLen>) -> DispatchResult {
```

## How to fix

1. Write a benchmark for the call.
2. Generate `weights.rs` from the benchmark.
3. Use the generated `WeightInfo` function in the attribute.

## Limits

- The rule skips test files.
- It skips a root-only call that compiles only for a test network: a `#[cfg]`
  needs a feature whose name contains `testnet`, and the body starts with
  `ensure_root(origin)?;`.
- It does not check weights that are small but not zero.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
