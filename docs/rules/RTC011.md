# RTC011 - `RemovePallet` deletes a live pallet

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | on | syntax | `remove-pallet-of-live-pallet` |

## What it finds

`frame_support::migrations::RemovePallet<N, _>`, where `N` is a string
parameter of the runtime crate, and its value is the name of a pallet that the
runtime still declares.

## Why it matters

`RemovePallet` deletes all keys under the pallet prefix on each runtime
upgrade, not only once. If the pallet is still in the runtime, each later
upgrade deletes its live state. Asset Hub Westend kept
`RemovePallet<PsmName, _>` (`PsmName = "Psm"`) after it ran, with
`Psm: pallet_psm = 65` still in the runtime.
[polkadot-sdk#13137](https://github.com/paritytech/polkadot-sdk/pull/13137)
removed it.

## How to fix

Remove the `RemovePallet` entry after it has run. If you meant to remove the
pallet, remove it from the runtime too.

## Limits

- `N` must be a `parameter_types!` entry or a `const` with a string literal
  value, in a production file of the crate. Else the rule does not report.
- A commented-out pallet entry is not live.
- A deliberate reset of a live pallet for one release is also reported. Remove
  the entry after that release.
- Measured: about 30 `RemovePallet` uses in polkadot-sdk,
  polkadot-fellows/runtimes, KILT and Moonbeam: 0 findings. 1 finding on Asset
  Hub Westend before #13137, 0 after.

Runtime scope: see [Runtime configuration rules](runtime-config.md).

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
