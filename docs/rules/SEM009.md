# SEM009 - Redundant contains_key Before remove or take

> **Severity:** Advisory · **Family:** semantic · **Engine:** compiler-backed (rustc driver) · **Rule name:** `redundant-contains-key-before-remove`

## Description

Storage access is one of the most expensive things a Substrate runtime does. Each read hits the state database and, on a parachain, pulls the touched trie nodes into the block's state proof (PoV), consuming both weight dimensions. Best practice is therefore to make every storage access count and to avoid patterns that read the same key more times than necessary.

A common redundant pattern is guarding a removal with an existence check: `if MyMap::contains_key(&key) { MyMap::remove(&key); }`. FRAME's `remove()` is idempotent — removing a key that does not exist is a harmless no-op — so the `contains_key()` call adds a full extra storage read that changes nothing about the outcome. The same applies to `take()`, which already returns the (optional) previous value; if the code needs to know whether the key existed, inspecting the result of `take()` is strictly cheaper than checking first.

Individually this is a small inefficiency, but dispatchable weights must cover worst-case storage access, so redundant reads inflate the declared weight of every call — or worse, go unaccounted for. Across hot paths and hooks the wasted reads add up to real throughput loss.

## What it detects

- An `if` expression whose condition is a resolved FRAME storage `contains_key(..)` call, where the `then` branch calls `remove(..)` or `take(..)` on the **same storage item with the same key bindings** (verified through compiler type resolution; calls inside closures in the branch are not matched).

## What should be avoided

```rust
pub fn cancel_offer(origin: OriginFor<T>, item: T::ItemId) -> DispatchResult {
    let who = ensure_signed(origin)?;
    // ❌ contains_key is a wasted storage read: remove() is already a no-op
    //    when the key is absent
    if Offers::<T>::contains_key(&who, &item) {
        Offers::<T>::remove(&who, &item);
    }
    Ok(())
}
```

The existence check performs a full storage read (and PoV contribution) only to gate an operation that is safe to run unconditionally.

## Best practice

```rust
// ✅ Option 1: remove unconditionally
pub fn cancel_offer(origin: OriginFor<T>, item: T::ItemId) -> DispatchResult {
    let who = ensure_signed(origin)?;
    Offers::<T>::remove(&who, &item);
    Ok(())
}
```

```rust
// ✅ Option 2: if existence matters, use take() and inspect the result
pub fn cancel_offer(origin: OriginFor<T>, item: T::ItemId) -> DispatchResult {
    let who = ensure_signed(origin)?;
    let offer = Offers::<T>::take(&who, &item).ok_or(Error::<T>::NoOffer)?;
    Self::deposit_event(Event::OfferCancelled { who, item, price: offer.price });
    Ok(())
}
```

Both options touch the key exactly once instead of twice.
