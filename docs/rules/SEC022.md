# SEC022 - Discarded origin check

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | on | compiler (needs the driver) | `discarded-origin-check` |

## What it finds

Code calls a FRAME origin check and drops its `Result`.

## Why it matters

`ensure_signed`, `ensure_root` and `EnsureOrigin::ensure_origin` report a bad
origin only through the `Result`. If the code drops the `Result`, any origin
passes. Polkadot runtime 2.0.1 had this bug in
`pallet-election-provider-multi-block`: any signed account could run the admin
call `manage`.
[polkadot-sdk#10248](https://github.com/paritytech/polkadot-sdk/pull/10248)
fixed it.

## Example

```rust
// Bad: any origin passes.
let _ = T::AdminOrigin::ensure_origin(origin);

// Good:
T::AdminOrigin::ensure_origin(origin)?;
```

## How to fix

Use `?` on the check, or use its result in a condition.

## How it decides

- Origin checks: `frame_system::{ensure_signed, ensure_root, ensure_none,
  ensure_signed_or_root, ensure_authorized}`, and `ensure_origin`,
  `try_origin` and `ensure_origin_or_root` of `EnsureOrigin` and
  `EnsureOriginWithArg`. The rule resolves the trait, so
  `T::AdminOrigin::ensure_origin` and concrete impls both count.
- Dropped means: a statement, `let _ =`, or an unused `_`-prefixed name. This
  also applies after `.ok()`, `.err()`, `.map(..)`, `.map_err(..)`, `.is_ok()`
  or `.is_err()`.
- The rule checks closure bodies, so it sees dispatchables.
- It skips test and benchmark code: items whose `cfg` requires `test` or
  `feature = "runtime-benchmarks"`, test and benchmark files, and crates whose
  name contains `benchmark`. `not(test)` and `any(test, x)` do not cause a skip.

## Limits

Not reported: a check with `?`, a check in a condition, a check bound to a
variable that is used later, and a returned check.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
