# SEC022 - Discarded Origin Check

> **Severity:** Error · **Family:** security · **Engine:** compiler-backed (rustc driver) · **Rule name:** `discarded-origin-check`

> **Off by default.** It catches the runtime 2.0.1 EPMB incident (and covers dispatchables, which SEC007 cannot see), but final review reproduced false positives in benchmark-only code behind compound cfgs such as `#[cfg(all(feature = "runtime-benchmarks", not(..)))]`, which the test/bench filter does not recognise yet. Enable with `SEC022 = true` under `[rules.enabled]`, or run `config/all-rules.toml`.

## Description

`ensure_signed`, `ensure_root` and `EnsureOrigin::ensure_origin` report a bad origin only through their `Result`. If the `Result` is discarded, that origin requirement is not enforced: the call runs for every origin, or only checks whatever weaker requirement follows.

Polkadot runtime 2.0.1 shipped this bug in `pallet-election-provider-multi-block`. `manage` started with `let _ = T::AdminOrigin::ensure_origin(origin);`, so any signed account could run the admin operations. Fixed by [paritytech/polkadot-sdk#10248](https://github.com/paritytech/polkadot-sdk/pull/10248).

SEC007 does not catch it. FRAME wraps every dispatchable body in a `with_storage_layer` closure, and SEC007 visits only function bodies, not closures.

## What it detects

A call to a FRAME origin check whose `Result` is dropped:

- origin checks: `frame_system::{ensure_signed, ensure_root, ensure_none, ensure_signed_or_root, ensure_authorized}`, and `ensure_origin`, `try_origin` and `ensure_origin_or_root` of frame-support's `EnsureOrigin` / `EnsureOriginWithArg` (resolved through the trait, so `T::AdminOrigin::ensure_origin` and concrete impls both count);
- discarded means used as a statement, bound to `let _ = ..` or to an `_`-prefixed name that is never used, after any of `.ok()`, `.err()`, `.map(..)`, `.map_err(..)`, `.is_ok()`, `.is_err()`.

The rule checks closure bodies too, so dispatchables are covered. Code compiled only for tests or benchmarks is skipped: items under `#[cfg(test)]` or `#[cfg(feature = "runtime-benchmarks")]`, test and benchmarking files (the same path classification the source rules use), and crates whose name contains `benchmark`.

## What should be avoided

```rust
pub fn manage(origin: OriginFor<T>, op: AdminOperation<T>) -> DispatchResultWithPostInfo {
    let _ = T::AdminOrigin::ensure_origin(origin); // ❌ any origin passes
    ...
}
```

## Best practice

```rust
pub fn manage(origin: OriginFor<T>, op: AdminOperation<T>) -> DispatchResultWithPostInfo {
    T::AdminOrigin::ensure_origin(origin)?; // ✅
    ...
}
```

## Precision and scope

Not reported: checks propagated with `?`, used in a condition (`if T::X::try_origin(o).is_ok()`), bound to a variable (even `_`-prefixed) that is used later, or returned. Overlaps with SEC007 only for `let _ = <origin check>;` in a plain function body (not a closure). There both rules report.

## Configuration

```toml
[rules.enabled]
"SEC022" = false
```

There are no rule-specific configuration keys beyond severity and enablement.
