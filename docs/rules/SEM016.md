# SEM016 - Missing AuthorizeCall in CreateAuthorizedTransaction

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | compiler (needs the driver) | `missing-authorizecall-in-create-authorized-transaction` |

## What it finds

An `impl CreateAuthorizedTransaction` whose `create_extension()` does not
construct `frame_system::AuthorizeCall::new()`.

## Why it matters

`AuthorizeCall` runs the call's `#[pallet::authorize]` closure and charges its
weight. Without it, transactions that the runtime creates (usually from
offchain workers) skip that check. The pool then rejects them, or accepts them
without the pallet's authorization check. The code compiles in both cases.

## Example

```rust
// Bad: no AuthorizeCall.
fn create_extension() -> Self::Extension {
    (
        frame_system::CheckNonZeroSender::<Runtime>::new(),
        frame_system::CheckWeight::<Runtime>::new(),
    )
}
```

```rust
// Good:
fn create_extension() -> Self::Extension {
    (
        frame_system::AuthorizeCall::<Runtime>::new(),
        frame_system::CheckNonZeroSender::<Runtime>::new(),
        frame_system::CheckWeight::<Runtime>::new(),
    )
}
```

## How to fix

Add `frame_system::AuthorizeCall::<Runtime>::new()` to the extension tuple.

## How it decides

The compiler resolves the trait and the called function. Renamed imports and
aliases are found.

## Limits

The rule needs the driver. A `--syntax-only` run does not check it.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
