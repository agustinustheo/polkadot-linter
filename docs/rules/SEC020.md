# SEC020 - Discarded Verification Verdict

> **Severity:** Error · **Family:** security · **Engine:** compiler-backed (rustc driver) · **Rule name:** `discarded-verification-result`

## Description

Many verifiers report a bad proof as a value, not as an error: `fn verify_ancestor(..) -> Result<bool, Error>` returns `Ok(false)` for a well-formed but invalid proof. `Err` means only that the verifier could not run. Propagating such a call with `?` and ignoring the `bool` turns every invalid proof into a success.

[paritytech/polkadot-sdk#11738](https://github.com/paritytech/polkadot-sdk/pull/11738) fixed exactly this in `pallet-mmr`. `verify_ancestry_proof` ran `raw_ancestry_proof.verify_ancestor(..).map_err(..)?;` and returned the previous root. A forged ancestry proof was accepted, and BEEFY fork-voting equivocation reports could then slash honest validators.

## What it detects

A call to a function whose name contains `verify`, or is `is_valid`, `check_signature` or `validate_proof`, whose rustc-resolved return type is `bool`, `Result<bool, _>` or `Option<bool>`, and whose verdict is dropped:

- used as a statement, including after `?` (`verify(..)?;`);
- bound to `let _ = ..`;
- reduced with `.is_ok()`, `.is_err()`, `.is_some()` or `.is_none()`;
- mapped away with `.map(|_| ..)` or `.and_then(|_| ..)`.

Verdict-preserving adapters (`map_err`, `inspect_err`, `ok`, `ok_or*`, `unwrap*`, `expect`) are followed. `inspect(|v| ..)` hands the verdict to a closure that may check it (`inspect(|valid| assert!(*valid))`), so it counts as inspected.

## What should be avoided

```rust
raw_ancestry_proof
    .verify_ancestor(Node::Hash(root), prev_root.clone())
    .map_err(|e| Error::Verify.log_debug(e))?; // ❌ Ok(false) is accepted
Ok(prev_root.hash())
```

## Best practice

```rust
let is_valid = raw_ancestry_proof
    .verify_ancestor(Node::Hash(root), prev_root.clone())
    .map_err(|e| Error::Verify.log_debug(e))?;
if !is_valid {
    return Err(Error::Verify.log_debug("invalid ancestry proof")); // ✅
}
Ok(prev_root.hash())
```

## Precision and scope

The verdict counts as inspected when it is used in a condition (`if`, `ensure!`, `assert!`, `== true`, `unwrap_or(false)` in a condition), bound to a named variable, or returned to the caller. Binding it to a named variable and never reading it is left to rustc's `unused_variables` lint. `#[cfg(test)]` code is not compiled by the linter's `cargo check` and is therefore not reported.
