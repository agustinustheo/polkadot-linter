# SEC020 - Discarded verification verdict

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | on | compiler (needs the driver) | `discarded-verification-result` |

## What it finds

Code calls a verifier that returns `bool`, `Result<bool, _>` or
`Option<bool>`, and then drops the `bool` verdict.

## Why it matters

Many verifiers return `Ok(false)` for an invalid proof. `Err` means only that
the verifier could not run. If the code uses `?` and ignores the `bool`, every
invalid proof passes.
[polkadot-sdk#11738](https://github.com/paritytech/polkadot-sdk/pull/11738)
fixed this bug in `pallet-mmr`. A forged ancestry proof was accepted, so BEEFY
equivocation reports could slash honest validators.

## Example

```rust
// Bad: Ok(false) is accepted.
raw_ancestry_proof
    .verify_ancestor(Node::Hash(root), prev_root.clone())
    .map_err(|e| Error::Verify.log_debug(e))?;
Ok(prev_root.hash())

// Good: the verdict is checked.
let is_valid = raw_ancestry_proof
    .verify_ancestor(Node::Hash(root), prev_root.clone())
    .map_err(|e| Error::Verify.log_debug(e))?;
if !is_valid {
    return Err(Error::Verify.log_debug("invalid ancestry proof"));
}
Ok(prev_root.hash())
```

## How to fix

Bind the verdict. Reject the input when the verdict is `false`.

## How it decides

A verifier is a function whose name contains `verify`, or is `is_valid`,
`check_signature` or `validate_proof`. The rule reports the verdict as dropped
in these cases:

- The call is a statement, also after `?`.
- The result is bound to `let _ =`.
- The result goes to `.is_ok()`, `.is_err()`, `.is_some()` or `.is_none()`.
- The result goes to `.map(|_| ..)` or `.and_then(|_| ..)`.

The rule follows `map_err`, `inspect_err`, `ok`, `ok_or*`, `unwrap*` and
`expect`. The verdict is checked when it is used in a condition, bound to a
named variable, returned, or passed to `inspect(|v| ..)`.

## Limits

- A named variable that is never read is not reported. Rustc's
  `unused_variables` lint covers it.
- `#[cfg(test)]` code is not compiled, so it is not checked.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
