# RTC007 - XCM deny barrier not applied to nested programs

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `xcm-deny-barrier-not-recursive` |

## What it finds

A `DenyThenTry` barrier uses a deny that inspects instructions, and the deny is
not wrapped in `DenyRecursively`.

## Why it matters

`DenyThenTry<Deny, Allow>` checks only the top-level instructions of a message.
Some instructions contain a nested XCM program: `SetAppendix`,
`SetErrorHandler` and `ExecuteWithOrigin`. The executor runs the nested program
locally. It does not run the barrier on the nested program. So an attacker can
put a denied instruction inside one of these instructions, and the deny does
not see it ([polkadot-sdk#7148](https://github.com/paritytech/polkadot-sdk/issues/7148)).

`DenyRecursively<Inner>` applies `Inner` to the top-level message and to every
nested program.
[polkadot-sdk#7200](https://github.com/paritytech/polkadot-sdk/pull/7200)
added it and used it in all SDK system runtimes.

## Example

```rust
// Bad: SetAppendix(Xcm(vec![InitiateReserveWithdraw { .. }])) passes the deny.
pub type Barrier = TrailingSetTopicAsId<
    DenyThenTry<
        DenyReserveTransferToRelayChain,
        (TakeWeightCredit, AllowTopLevelPaidExecutionFrom<Everything>),
    >,
>;
```

```rust
// Good
pub type Barrier = TrailingSetTopicAsId<
    DenyThenTry<
        DenyRecursively<DenyReserveTransferToRelayChain>,
        (TakeWeightCredit, AllowTopLevelPaidExecutionFrom<Everything>),
    >,
>;
```

## How to fix

Wrap each instruction-inspecting deny in `DenyRecursively<..>`.

## How it decides

It reports these denies when they are not inside `DenyRecursively`:

- `DenyReserveTransferToRelayChain` (xcm-builder)
- `DenyExportMessageFrom` (bridge-hubs common)

It also looks inside tuples and same-file `type` aliases.

## Limits

- It does not report other denies, such as runtime-local ones. A deny that does
  not inspect instructions (for example `DenyOnceMigrationStarts`) is safe.
- Evidence: 10 findings on the parent of #7200, exactly the 10 files that #7200
  changed. 0 after the merge. 9 findings on polkadot-fellows/runtimes main
  (`711471a24`).

Runtime scope: see [Runtime configuration rules](runtime-config.md).

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
