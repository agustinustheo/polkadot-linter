# TRM001 - Spelling and Terminology Conventions

> **Severity:** Advisory · **Family:** terminology · **Engine:** source analysis (syn) · **Rule name:** `spelling-conventions`

## Description

A pallet's comments, doc strings, error messages, and identifiers are part of its public interface. Inconsistent spelling ("initialise" next to "initialize") and drifting terminology (calling the same concept "substrate", "the SDK", and "the framework" in different files) make documentation harder to search, reviews noisier, and generated rustdoc look unpolished. Typos in user-facing strings — event descriptions, log messages, RPC error text — ship to every downstream integrator and are awkward to fix later because tooling and dashboards may already match on the misspelled text.

In an ecosystem context this matters more than in an ordinary library: pallet docs are rendered into chain documentation portals, metadata strings surface in wallets and explorers, and grep-ability across a large workspace depends on everyone spelling a term the same way. Established projects therefore pin a spelling convention (for example, American/"Google" English) and a small dictionary of project-specific term substitutions, and enforce them mechanically rather than through review comments.

This rule is that mechanical enforcement. It is intentionally **dormant by default**: it does nothing until you populate the `[terminology.british_english]` and/or `[terminology.forbidden_terms]` dictionaries in `polkadot-linter.toml` — both tables ship commented out. Once populated, the linter flags each configured word with the preferred replacement.

## What it detects

Only when at least one dictionary is configured, and only in Rust or text files:

- Words from `[terminology.british_english]` (matched case-insensitively, on word boundaries), reported as "Non-standard spelling `X` — prefer `Y`".
- Terms from `[terminology.forbidden_terms]` (matched case-sensitively, on word boundaries), reported as "Forbidden term `X` — use `Y` instead".
- Text scanned per line: whole lines in text files; comment text (`//`, `///`, `//!`, and inline trailing comments) and `#[doc]` attributes in Rust files; string literal contents when `check_strings = true`; and remaining code (identifiers) only when `check_identifiers = true`.
- Lines containing SPDX / Copyright / license headers are always skipped.

## What should be avoided

```rust
// ❌ mixed conventions scattered through one pallet
/// Initialises the colour palette for the current era.
pub fn init_palette(origin: OriginFor<T>) -> DispatchResult {
    let who = ensure_signed(origin)?;
    log::info!("initialising behaviour for {who:?}"); // British spelling in a shipped string
    Ok(())
}
```

Docs and log strings mix British and American spellings, so searching the workspace for "initializ" or "color" silently misses these occurrences.

## Best practice

```rust
// ✅ one convention, applied everywhere
/// Initializes the color palette for the current era.
pub fn init_palette(origin: OriginFor<T>) -> DispatchResult {
    let who = ensure_signed(origin)?;
    log::info!("initializing behavior for {who:?}");
    Ok(())
}
```

Pick one spelling standard for the project, encode it in the linter config below, and let CI keep every comment, doc string, and message consistent.

## Configuration

The rule stays inactive until at least one dictionary entry is uncommented:

```toml
[rules.severity]
"TRM001" = "advisory"

[rules.enabled]
"TRM001" = false

[terminology]
check_strings = true      # also scan string literal contents in code
check_identifiers = false # also scan remaining code text (identifiers)

[terminology.british_english]
# non-preferred = preferred (case-insensitive match)
"optimisation" = "optimization"
"initialise" = "initialize"

[terminology.forbidden_terms]
# project-specific vocabulary (case-sensitive match)
"substrate" = "Polkadot SDK"
```

- `check_strings` (default `true`): include string literal contents on code lines.
- `check_identifiers` (default `false`): when a code line has no comment or checkable string, scan the code text itself.
