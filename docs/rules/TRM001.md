# TRM001 - Spelling and terminology

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| advisory | on, but inactive until configured | syntax | `spelling-conventions` |

## What it finds

Words in comments, docs and strings that your project dictionary marks as wrong.

## Why it matters

One spelling for each term makes code and docs easy to search. Strings in
events and logs reach wallets, explorers and dashboards. They are hard to
change later.

## Example

With `"initialise" = "initialize"` configured:

```rust
// Bad:
/// Initialises the palette.
```

```rust
// Good:
/// Initializes the palette.
```

## How to fix

Use the preferred word that the finding shows.

## How it decides

- The rule does nothing until one dictionary has an entry. Both ship empty.
- `[terminology.british_english]` entries match without case, on word
  boundaries.
- `[terminology.forbidden_terms]` entries match with case, on word boundaries.
- It checks whole lines in text files. In Rust files it checks comments and
  `#[doc]` attributes. It also checks strings and identifiers if you turn them on.
- It skips SPDX, copyright and license lines.

## Configuration

```toml
[terminology]
severity = "advisory"
check_strings = true       # check string literals (default true)
check_identifiers = false  # check code text with no comment or string (default false)

[terminology.british_english]   # non-preferred = preferred
"initialise" = "initialize"

[terminology.forbidden_terms]   # forbidden = preferred
"substrate" = "Polkadot SDK"
```
