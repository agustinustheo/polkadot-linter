# SEM014 - Missing log target near SubmitTransaction

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| advisory | on | syntax | `submit-transaction-log-target` |

## What it finds

A `log::` macro near an offchain `SubmitTransaction::<..>::submit_transaction`
call has no `target:` argument.

## Why it matters

A failed offchain submission leaves no event and no storage change. The node
log is the only record. Without a target, operators cannot filter the log for
your pallet.

## Example

```rust
// Bad: no target.
match SubmitTransaction::<T, Call<T>>::submit_transaction(xt) {
    Ok(()) => log::debug!("submitted price update"),
    Err(e) => log::error!("failed to submit price update: {e:?}"),
}
```

```rust
// Good:
const LOG_TARGET: &str = "runtime::price-oracle";
match SubmitTransaction::<T, Call<T>>::submit_transaction(xt) {
    Ok(()) => log::debug!(target: LOG_TARGET, "submitted price update"),
    Err(e) => log::error!(target: LOG_TARGET, "failed to submit price update: {e:?}"),
}
```

## How to fix

1. Define one `LOG_TARGET` constant for the pallet.
2. Add `target: LOG_TARGET` to each log call.

Operators can then run the node with `-l runtime::price-oracle=trace`.

## How it decides

The rule finds a line that contains `SubmitTransaction::<` and
`submit_transaction`. It checks the `log::trace!` to `log::error!` calls in
the next 12 lines.

## Limits

- The rule skips test files and `#[cfg(test)]` modules.
- It does not see log calls more than 12 lines after the submission.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
