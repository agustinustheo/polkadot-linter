# BEN003 - Extrinsic Without a Benchmark

> **Severity:** Warning · **Family:** benchmark · **Engine:** source analysis (syn) · **Rule name:** `extrinsic-without-benchmark`

## Description

Every dispatchable is a promise: "including me costs this much block weight." A new extrinsic added to a `#[pallet::call]` block without a benchmark has no measured basis for that promise. In practice its `#[pallet::weight]` ends up as a constant borrowed from a neighbouring call or an optimistic guess — and as Libro's "Benchmark Extrinsic Worst Case Scenario" chapter stresses, even measured weights must reflect the *heaviest* possible execution path, not the typical one.

The consequences cut both ways. An underweighted extrinsic lets a block's declared weight fit within limits while its real execution time blows past them: on a parachain, the proof-of-validity may not be executable inside the relay chain's validation window, stalling the chain. It also underprices the call, handing attackers cheap block space for spam. An overweighted extrinsic wastes throughput and overcharges honest users. Both failure modes are invisible until the chain is under load — which is exactly when they hurt.

This rule enforces the entry ticket for new dispatchables: every `#[pallet::call_index]` function must have a benchmark to be measured by.

The rule authority matrix (`docs/rule-authority-matrix.md`) records BEN003's target authority as the rustc bridge, which matches compiler-confirmed dispatchables against compiled benchmark identities (pinned `pallet-assets` baseline). The syn implementation documented here performs the same cross-reference at the source level.

## What it detects

For each `lib.rs` that contains a `#[pallet::call]` block:

- dispatchables are collected as functions annotated `#[pallet::call_index]` inside the `#[pallet::call]` impl;
- benchmark names are collected from the sibling `benchmarking.rs` (or `benchmarks.rs`) — both v2 `#[benchmark]` functions and legacy `benchmarks! { ... }` entries;
- a diagnostic is emitted for every extrinsic with no matching benchmark. A benchmark matches if its name equals the extrinsic name or extends it with an underscore-separated suffix (e.g. `transfer_worst_case` matches `transfer`);
- if no benchmarking file exists next to `lib.rs` at all, every extrinsic is flagged.

## What should be avoided

```rust
#[pallet::call]
impl<T: Config> Pallet<T> {
    #[pallet::call_index(3)]
    #[pallet::weight(Weight::from_parts(10_000, 0))] // ❌ guessed constant
    pub fn merge_positions(origin: OriginFor<T>, count: u32) -> DispatchResult {
        let who = ensure_signed(origin)?;
        for _ in 0..count {
            Self::merge_next(&who)?; // real cost scales with `count`
        }
        Ok(())
    }
}
// benchmarking.rs has no `merge_positions` benchmark
```

The declared weight is a flat guess for a call whose cost scales with `count`; under load, blocks containing many such calls exceed their real execution budget.

## Best practice

```rust
// benchmarking.rs
#[benchmark]
fn merge_positions(c: Linear<1, { T::MaxPositions::get() }>) {
    let caller: T::AccountId = whitelisted_caller();
    setup_positions::<T>(&caller, c); // worst case: maximum mergeable positions

    #[extrinsic_call]
    _(RawOrigin::Signed(caller.clone()), c);

    assert_eq!(Positions::<T>::iter_prefix(&caller).count(), 1);
}
```

The benchmark parameterises over the scaling factor and sets up the worst case, so the generated `WeightInfo::merge_positions(c)` charges each call for what it can actually cost.
