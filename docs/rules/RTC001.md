# RTC001 - Placeholder WeightInfo in a Runtime Config

> **Severity:** Warning · **Family:** runtime-config · **Engine:** source analysis (syn) · **Rule name:** `placeholder-weight-info-in-runtime`

## Description

Every pallet's dispatchables are charged through its `Config::WeightInfo`. A pallet ships two placeholder implementations of that trait. The unit type `()` is documented in upstream `weights.rs` files as "for backwards compatibility and tests". For most FRAME pallets it carries real, non-zero numbers: the SDK's reference weights, benchmarked on reference hardware and priced with `RocksDbWeight`, not with this runtime's database weights, storage layout, or configuration. A few pallets return zero or flat weights there. `TestWeightInfo` types exist for mocks and return `Weight::zero()` or a flat constant with no proof size (for example `parachains_slashing::TestWeightInfo` and `pallet_xcm::TestWeightInfo`). Binding either one in a production runtime means extrinsics are charged for work that was never measured on this runtime. Underweight calls let attackers fill blocks cheaply and can push a parachain block past its PoV or execution limits.

## What it detects

Inside an `impl <path>::Config for Runtime` (including instanced `Config<I>`), any associated type whose name ends in `WeightInfo` (`WeightInfo`, `SystemWeightInfo`, `ExtensionsWeightInfo`, ...) bound to:

- `()`, unless the pallet is in `unit_weight_info_allowlist`;
- a path with a segment starting with `TestWeightInfo`, such as `pallet_xcm::TestWeightInfo`.

When `flag_substrate_weight = true`, a third variant reports upstream `<pallet>::weights::SubstrateWeight<Runtime>` bindings at `substrate_weight_severity` (advisory by default).

### Why `SubstrateWeight` is off by default

Upstream `SubstrateWeight` was benchmarked on the SDK reference runtime, and SR Labs reported it as Medium/High (Moonbeam S2-51, NeuroWeb 4.3, OpenZeppelin 2024-07 §3.2.2). However, at the pinned SDK commit the production runtimes and templates contain 13 such bindings, plus 59 in kitchensink. Several are deliberate, such as `pallet_revive` and `pallet_state_trie_migration`, which carry their own reference weights. That is too noisy to report as a default warning, so the variant is opt-in and advisory.

### Allowlisted unit weights

`pallet_babe`, `pallet_grandpa` and `pallet_beefy` implement `WeightInfo for ()` in a hand-written `default_weights.rs` ("This file was not auto-generated") that encodes the equivocation-proof cost formula. `type WeightInfo = ();` is the intended production binding for them and is allowlisted.

## Runtime scope

Production runtimes, system parachains, Westend/Rococo and the templates are inspected. `#[cfg(test)]` code, mock/test/bench paths and test runtime crates are never inspected. Dev runtimes (`dev_runtime_packages`) are skipped unless `include_dev_runtimes = true`. See [Runtime Configuration Rules](runtime-config.md).

## What should be avoided

```rust
impl pallet_xcm::Config for Runtime {
    type WeightInfo = pallet_xcm::TestWeightInfo; // ❌ flat constants, zero proof size
}

impl pallet_message_queue::Config for Runtime {
    type WeightInfo = (); // ❌ "for backwards compatibility and tests"
}
```

## Best practice

```rust
impl pallet_message_queue::Config for Runtime {
    type WeightInfo = weights::pallet_message_queue::WeightInfo<Runtime>;
}

frame_benchmarking::define_benchmarks!(
    [pallet_message_queue, MessageQueue]
    [pallet_xcm, PalletXcmExtrinsicsBenchmark::<Runtime>]
);
```

Benchmark every pallet in the runtime that will use the weights and bind the generated files.

## Configuration

```toml
[rules.severity]
"RTC001" = "warning"

[rules.enabled]
"RTC001" = false

[runtime_config]
unit_weight_info_allowlist = ["pallet_babe", "pallet_beefy", "pallet_grandpa"]
flag_substrate_weight = false
substrate_weight_severity = "advisory"
```

A per-rule `[rules.severity]` override applies to both variants.
