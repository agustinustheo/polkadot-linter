# RTC001 - Test WeightInfo in a runtime

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `placeholder-weight-info-in-runtime` |

## What it finds

An `impl <pallet>::Config for Runtime` binds a `*WeightInfo` type to a
`TestWeightInfo` type.

## Why it matters

These weights were never measured. `TestWeightInfo` returns zero or a flat
constant with no proof size. Calls that cost too little let an attacker fill
blocks cheaply and can push a block past its PoV limit. SR Labs reported this
as High in several audits (see References).

## Example

```rust
// Bad
impl pallet_xcm::Config for Runtime {
    type WeightInfo = pallet_xcm::TestWeightInfo;
}
```

```rust
// Good
impl pallet_xcm::Config for Runtime {
    type WeightInfo = weights::pallet_xcm::WeightInfo<Runtime>;
}
```

## How to fix

1. Add the pallet to `define_benchmarks!`.
2. Run the benchmarks on this runtime.
3. Bind the generated weights file.

## Limits

- It does not report `type WeightInfo = ();` or upstream `SubstrateWeight`.
  0.3.0 removed the `()` check: on 14 live parachain repositories, 1 of 62
  `()` bindings was worth a fix, because `()` usually has the SDK's benchmarked
  reference weights. The `unit_weight_info_allowlist`, `flag_substrate_weight`
  and `substrate_weight_severity` keys are now ignored, with a warning.
- Pinned SDK: 2 findings (parachain template `pallet_xcm`, Rococo
  `parachains_slashing`).

Runtime scope: see [Runtime configuration rules](runtime-config.md).
