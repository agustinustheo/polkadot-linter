# SEM008 - Deprecated sp_std Paths

> **Severity:** Warning · **Family:** semantic · **Engine:** source analysis (syn) · **Rule name:** `sp-std-deprecated`

## Description

Runtime code compiles to `no_std` Wasm, so it cannot use Rust's `std` library directly. Historically, Substrate shipped the `sp-std` crate as a facade that re-exported the needed collections and primitives (`sp_std::vec::Vec`, `sp_std::collections::btree_map::BTreeMap`, and so on) in a way that worked in both native and Wasm builds.

The Rust ecosystem has a standard answer to this problem: the `alloc` and `core` crates, which are available in every `no_std` environment. The Polkadot SDK deprecated `sp-std` in favor of using `alloc` and `core` directly. New code that still imports through `sp_std::` accumulates a dependency on a deprecated crate that upstream is removing, makes future SDK upgrades noisier, and diverges from how the rest of the ecosystem (and current polkadot-sdk pallets) is written.

The migration is straightforward: declare `extern crate alloc;` in the crate root and import from `alloc::` (for heap types like `Vec`, `String`, `BTreeMap`, `boxed::Box`) or `core::` (for `marker`, `ops`, `fmt`, etc.).

## What it detects

- Any line of Rust code containing a path through `sp_std::` (for example `use sp_std::vec::Vec;` or an inline `sp_std::marker::PhantomData` reference).
- Occurrences inside string literals and line comments are ignored.

## What should be avoided

```rust
// ❌ imports through the deprecated sp-std facade
use sp_std::vec::Vec;
use sp_std::collections::btree_map::BTreeMap;

pub fn sorted_holders<T: Config>() -> Vec<T::AccountId> {
    let map: BTreeMap<T::AccountId, BalanceOf<T>> = Holders::<T>::iter().collect();
    map.into_keys().collect()
}
```

Every `sp_std::` path keeps the crate tied to a deprecated dependency and will break once `sp-std` is dropped from the SDK.

## Best practice

```rust
// ✅ in the crate root (lib.rs)
extern crate alloc;

// ✅ import from alloc/core directly
use alloc::{collections::btree_map::BTreeMap, vec::Vec};

pub fn sorted_holders<T: Config>() -> Vec<T::AccountId> {
    let map: BTreeMap<T::AccountId, BalanceOf<T>> = Holders::<T>::iter().collect();
    map.into_keys().collect()
}
```

`alloc` provides all heap-allocated types in `no_std` builds; anything that does not allocate (traits, markers, formatting) lives in `core`.
