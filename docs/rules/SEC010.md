# SEC010 - Hook writes storage without a storage layer

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | compiler (needs the driver) | `missing-transactional-in-hook` |

## What it finds

A FRAME hook writes storage two or more times, and a `?` after a write can
return early. The writes are not in a storage layer.

## Why it matters

FRAME rolls back a dispatchable's writes when it returns `Err`. FRAME does not
do this for hooks. If a hook returns early, the earlier writes stay and the
later writes do not occur. The state is then only partly updated, and no
event or user shows the cause.

## Example

```rust
// Bad: two writes, then a fallible step.
fn on_initialize(_n: BlockNumberFor<T>) -> Weight {
    let _ = (|| -> DispatchResult {
        QueueHead::<T>::put(next_head);
        QueueLen::<T>::mutate(|len| *len = len.saturating_sub(1));
        Self::settle_item(next_head)?;
        Ok(())
    })();
    T::WeightInfo::on_initialize()
}

// Good: an error rolls back all writes in the closure.
fn on_initialize(_n: BlockNumberFor<T>) -> Weight {
    let _ = with_storage_layer::<(), DispatchError, _>(|| {
        QueueHead::<T>::put(next_head);
        QueueLen::<T>::mutate(|len| *len = len.saturating_sub(1));
        Self::settle_item(next_head)?;
        Ok(())
    });
    T::WeightInfo::on_initialize()
}
```

## How to fix

Do one of these:

- Put the writes and the fallible step in `with_storage_layer` or
  `with_transaction`.
- Add `#[transactional]` to the hook.
- Do all fallible work first. Write storage only after it succeeds.

## How it decides

The rule checks `on_initialize`, `on_finalize`, `on_idle` and `on_poll` in
`Hooks` impls. It counts resolved FRAME storage writes: `put`, `insert`,
`mutate`, `remove`, `kill` and `set`. It reports a hook with two or more writes
and a `?` after a write. It skips a hook with `#[transactional]`, and writes
inside a storage-layer closure. The message gives the number of writes.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
