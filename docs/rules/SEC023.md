# SEC023 - Option Equality in an Origin Check

> **Severity:** Error · **Family:** security · **Engine:** compiler-backed (rustc driver) · **Rule name:** `option-equality-authorization`

## Description

Comparing two `Option`s to authorize a caller treats "both unknown" as a match: `None == None` is `true`. If the caller's account cannot be derived and the asset has no owner, the check passes.

[paritytech/polkadot-sdk#11910](https://github.com/paritytech/polkadot-sdk/pull/11910) fixed this in Snowbridge's `ForeignAssetOwner::try_origin` (`bridges/snowbridge/runtime/runtime-common/src/v2/register_token.rs`), backported in #13531. The asset `owner` and the origin's `from` account were both `Option<AccountId>` and the check was `if from != owner { return Err(origin) }`. The fix unwraps each side with `ok_or_else(..)?` before comparing.

## What it detects

Inside a method of (or implementing) frame-support's `EnsureOrigin` / `EnsureOriginWithArg`, including closures in it, an `if` (or `ensure!`) where all of these hold:

- the condition is `a != b`, or `a == b` under a single `!` (the `ensure!(a == b, ..)` form). Ordering comparisons (`<`, `>`, `<=`, `>=`) are never reported;
- both operands have rustc-resolved type `Option<_>` (references peeled), and neither is provably `Some`/`None`: not a literal `Some(..)` or `None`, not a local bound from one, and not checked earlier in the same function with `.is_none()`, `.is_some()`, `if let Some(..) =` or `let Some(..) = .. else` (matched by source text, so any earlier check of the same expression suppresses);
- the branch taken when the two differ rejects by itself (as in [SEC021](SEC021.md)), and the `else` branch, if any, does not.

## What should be avoided

```rust
let owner = AssetInspect::owner(asset_location.into());           // Option<AccountId>
let from = LocationToAccountId::convert_location(&location);      // Option<AccountId>
if from != owner {
    return Err(origin); // ❌ None == None reaches Ok
}
```

## Best practice

```rust
let owner = AssetInspect::owner(asset_location.into()).ok_or_else(|| origin.clone())?;
let from = LocationToAccountId::convert_location(&location).ok_or_else(|| origin.clone())?;
if from != owner {
    return Err(origin); // ✅
}
```

## Precision and scope

Limited to `EnsureOrigin*` methods. Elsewhere, `None == None` is often the intended semantics. XCM `ExpectOrigin(None)`, for example, asserts that there is no origin, and an unrestricted version of this rule reported it. Comparisons against a literal `Some(who)` are safe and not reported.
