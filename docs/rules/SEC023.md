# SEC023 - Option equality in an origin check

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | on | compiler (needs the driver) | `option-equality-authorization` |

## What it finds

An `EnsureOrigin` impl authorizes a caller by comparing two `Option` values.

## Why it matters

`None == None` is `true`. If the code cannot find the caller's account and the
asset has no owner, the check passes.
[polkadot-sdk#11910](https://github.com/paritytech/polkadot-sdk/pull/11910)
fixed this in Snowbridge's `ForeignAssetOwner::try_origin` (backported in
#13531).

## Example

```rust
// Bad: None == None reaches Ok.
let owner = AssetInspect::owner(asset_location.into());       // Option<AccountId>
let from = LocationToAccountId::convert_location(&location);  // Option<AccountId>
if from != owner {
    return Err(origin);
}

// Good: reject None first.
let owner = AssetInspect::owner(asset_location.into()).ok_or_else(|| origin.clone())?;
let from = LocationToAccountId::convert_location(&location).ok_or_else(|| origin.clone())?;
if from != owner {
    return Err(origin);
}
```

## How to fix

Convert each `Option` to a value, and reject `None`. Then compare the values.

## How it decides

The rule checks methods of `EnsureOrigin` and `EnsureOriginWithArg` impls. It
reports an `if` or `ensure!` when all these conditions are true:

1. The condition is `a != b`, or `!(a == b)` (the form `ensure!(a == b, ..)`
   makes). Ordering comparisons are not reported.
2. Both sides have the type `Option<_>`. Neither side is known to be `Some` or
   `None`. A side is known when it is a `Some(..)` or `None` literal, a local
   bound from one, or a value checked earlier with `.is_none()`, `.is_some()`,
   `if let Some(..)` or `let Some(..) = .. else`.
3. The branch for "different" rejects directly, as in [SEC021](SEC021.md). The
   `else` branch does not reject.

## Limits

- The rule checks only `EnsureOrigin*` methods. In other code, `None == None`
  is often correct. For example, XCM `ExpectOrigin(None)` checks that there is
  no origin.
- It does not check comparisons in closures.
- A comparison with a `Some(who)` literal is safe and is not reported.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
