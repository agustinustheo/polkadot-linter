# RTC002 - Pallet missing from define_benchmarks!

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `pallet-missing-from-define-benchmarks` |

## What it finds

A pallet binds a runtime-local weights file (`weights::<pallet>::WeightInfo`),
but the runtime's `define_benchmarks!` does not list the pallet.

## Why it matters

The benchmark CLI runs only the pallets in `define_benchmarks!`. A weights file
for a missing pallet cannot be generated again. It keeps old numbers, often
copied from another runtime, while the pallet code changes.

## Example

```rust
// Bad: pallet_sudo has local weights but no benchmark entry.
impl pallet_sudo::Config for Runtime {
    type WeightInfo = weights::pallet_sudo::WeightInfo<Runtime>;
}
frame_benchmarking::define_benchmarks!(
    [pallet_balances, Balances]
);
```

```rust
// Good
frame_benchmarking::define_benchmarks!(
    [pallet_balances, Balances]
    [pallet_sudo, Sudo]
);
```

## How to fix

1. Add the pallet to `define_benchmarks!`.
2. Run the benchmark and replace the weights file.

## How it decides

- The runtime must have at least one `define_benchmarks!`. Entries behind
  `#[cfg(feature = "runtime-benchmarks")]` count. Entries in `#[cfg(test)]`
  code do not count.
- The binding must be `weights::<module>::<Type>` or
  `crate::weights::<module>::<Type>`.
- The rule joins each path with `_`. An entry matches when the joined paths are
  equal, or when one path ends with all segments of the other. So
  `runtime_parachains::paras` matches `polkadot_runtime_parachains::paras`.
  One segment alone never matches.

## Limits

- It does not report upstream or placeholder weights. RTC001 reports those.
- One benchmarked instance covers all instances of an instanced pallet.
- It does not report a runtime that has no `define_benchmarks!`.
- Pinned SDK: 10 findings on Westend system chains and Rococo, all correct.

Runtime scope: see [Runtime configuration rules](runtime-config.md).

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
