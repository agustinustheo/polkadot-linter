# SEC015 - Unguarded dispatch_bypass_filter

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | compiler (needs the driver) | `dispatch-bypass-filter-in-production` |

## What it finds

Runtime code calls `dispatch_bypass_filter` on a path that has not proven a
root origin.

## Why it matters

Call filters (`BaseCallFilter`, proxy filters, safe mode) block calls that
governance has disabled. `dispatch_bypass_filter` skips all of these filters.
If a non-root caller can reach it, that caller can run disabled calls, also
during an emergency pause.

## Example

```rust
// Bad: any member skips the call filters.
let who = ensure_signed(origin)?;
ensure!(Members::<T>::contains_key(&who), Error::<T>::NotMember);
call.dispatch_bypass_filter(frame_system::RawOrigin::Signed(who).into())

// Good: the call filters still apply.
call.dispatch(frame_system::RawOrigin::Signed(who).into())

// Good: root is proven on this path.
if frame_system::ensure_root(origin.clone()).is_ok() {
    return call.dispatch_bypass_filter(frame_system::RawOrigin::Root.into()) /* ... */;
}
```

## How to fix

Do one of these:

- Use `dispatch` so that the filters apply.
- Put the bypass in the `then` branch of
  `if frame_system::ensure_root(origin).is_ok()`.

## How it decides

The rule resolves the call by type, so it finds calls through traits and
re-exports. It checks code reachable from dispatchables and FRAME hooks. It
accepts only an `ensure_root(..).is_ok()` guard on the same path. A different
strict origin check is still reported.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
