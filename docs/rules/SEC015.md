# SEC015 - Unguarded dispatch_bypass_filter in Production Code

> **Severity:** Warning · **Family:** security · **Engine:** compiler-backed (rustc driver) · **Rule name:** `dispatch-bypass-filter-in-production`

## Description

Runtimes use call filters (`BaseCallFilter`, proxy filters, pause/maintenance filters) as a last line of defence: even if a call can be constructed, the filter decides whether the current origin may dispatch it. Governance routinely relies on this to disable broken or dangerous extrinsics, put a chain into safe mode, or restrict what a proxy may do on behalf of an account.

`dispatch_bypass_filter` deliberately skips that entire layer. It exists for cases where the caller has *already* proven maximum privilege — typically after an `ensure_root` check — and must be able to act even while filters are engaged (for example, governance rescuing a paused chain). Called anywhere else, it quietly re-enables every call the runtime operators thought they had filtered out: a pallet that forwards user-influenced calls through `dispatch_bypass_filter` turns a "this extrinsic is disabled" guarantee into a fiction and can hand unprivileged users a path around safe mode, proxy restrictions, or emergency pauses.

Because the bypass is invisible at the call site of the *outer* extrinsic, these bugs survive review easily. This rule makes every unguarded bypass explicit so each one carries a visible root-privilege justification.

## What it detects

- A resolved call to `frame_support`'s `dispatch_bypass_filter` in any function body reachable from a runtime entry point (dispatchables and FRAME hooks).
- The call is not flagged when it sits inside the `then`-branch of an `if frame_system::ensure_root(origin).is_ok()` guard — i.e. when root privilege has been established on that exact path.
- Resolution is type-based, so calls through trait methods and re-exports are found, and unrelated functions that merely share the name are not.

## What should be avoided

```rust
#[pallet::call_index(0)]
#[pallet::weight(T::WeightInfo::execute())]
pub fn execute(origin: OriginFor<T>, call: Box<<T as Config>::RuntimeCall>) -> DispatchResult {
    let who = ensure_signed(origin)?;
    ensure!(Members::<T>::contains_key(&who), Error::<T>::NotMember);
    // ❌ member-gated, but skips BaseCallFilter and safe-mode filters
    call.dispatch_bypass_filter(frame_system::RawOrigin::Signed(who).into())
        .map(|_| ())
        .map_err(|e| e.error)
}
```

Any member can now dispatch calls the runtime has explicitly filtered out — including extrinsics disabled during an emergency pause.

## Best practice

Option 1 — dispatch normally so filters still apply:

```rust
pub fn execute(origin: OriginFor<T>, call: Box<<T as Config>::RuntimeCall>) -> DispatchResult {
    let who = ensure_signed(origin)?;
    ensure!(Members::<T>::contains_key(&who), Error::<T>::NotMember);
    // ✅ respects BaseCallFilter and any active call filters
    call.dispatch(frame_system::RawOrigin::Signed(who).into())
        .map(|_| ())
        .map_err(|e| e.error)
}
```

Option 2 — reserve the bypass for a proven root path:

```rust
pub fn force_execute(origin: OriginFor<T>, call: Box<<T as Config>::RuntimeCall>) -> DispatchResult {
    if frame_system::ensure_root(origin.clone()).is_ok() {
        // ✅ root established on this path; bypass is intentional
        return call
            .dispatch_bypass_filter(frame_system::RawOrigin::Root.into())
            .map(|_| ())
            .map_err(|e| e.error);
    }
    Err(DispatchError::BadOrigin.into())
}
```

Root (or an equivalently strict configured origin) is the only origin that should be able to act while filters are engaged; establishing it immediately before the bypass makes the privilege escalation auditable.
