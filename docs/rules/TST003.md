# TST003 - Imports Inside Test Closures and Function Bodies

> **Severity:** Advisory · **Family:** test-smell · **Engine:** source analysis (syn) · **Rule name:** `imports-inside-closures`

## Description

Substrate test suites are built around closures — almost every test body runs inside `new_test_ext().execute_with(|| { ... })`. It is easy for `use` statements to accumulate inside those closures or deep inside test function bodies, especially after copy-pasting a test between files. Scattered local imports make it hard to see at a glance what a test module depends on, cause the same path to be imported repeatedly across tests, and produce noisy diffs when a type moves.

Keeping all imports at the module level is a readability and maintainability convention: one place to look, one place to update, and rustfmt/`cargo fix` tooling handles module-level imports far better than block-local ones. This is a style rule rather than a safety rule, hence the Advisory default.

The rule authority matrix (`docs/rule-authority-matrix.md`) keeps TST003 as a source-analysis rule permanently: import placement is lexical source style, and macro-expanded HIR would be a strictly weaker signal than the parser.

## What it detects

In test files:

- any `use` item that appears at block-nesting depth 2 or more — i.e. inside a closure body, or inside a block nested within a function body — rather than at the module level.

## What should be avoided

```rust
#[test]
fn stake_updates_ledger() {
    new_test_ext().execute_with(|| {
        use frame_support::traits::Currency;   // ❌ import buried in the closure
        use crate::Event;                      // ❌

        assert_ok!(Staking::stake(RuntimeOrigin::signed(1), 100));
        assert_eq!(Balances::total_balance(&1), 900);
    });
}
```

The module's real dependency set is hidden inside individual closures and gets duplicated as more tests need the same traits.

## Best practice

```rust
use frame_support::traits::Currency;
use crate::Event;

#[test]
fn stake_updates_ledger() {
    new_test_ext().execute_with(|| {
        assert_ok!(Staking::stake(RuntimeOrigin::signed(1), 100));
        assert_eq!(Balances::total_balance(&1), 900);
    });
}
```

All imports live at the top of the test module, shared by every test that needs them.
