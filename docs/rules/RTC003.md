# RTC003 - XCM Fees Waived or Delivery Free

> **Severity:** Error · **Family:** runtime-config · **Engine:** source analysis (syn) · **Rule name:** `xcm-fees-waived`

## Description

XCM delivery fees are the congestion control for cross-chain messaging. Senders pay per message and per byte, and exponential pricing makes a flood progressively more expensive. Two configuration points can switch this off:

- The executor's `FeeManager`. `WaiveDeliveryFees` returns `is_waived = true` for every origin, and `XcmFeeManagerFromComponents<WaivedLocations, _>` waives every origin that `WaivedLocations` contains, so `Everything` waives all of them.
- The delivery price of each router (`PriceForSiblingDelivery`, `PriceForParentDelivery`, `PriceForChildParachainDelivery`, or the third generic argument of `ParentAsUmp` / `ChildParachainRouter`). `()` and `NoPriceForMessageDelivery` return an empty price (`polkadot/runtime/common/src/xcm_sender.rs`).

In either case anyone can fill the outbound XCMP/UMP/DMP queues for the price of a local transaction, delaying or dropping other users' messages and growing storage until the queues drain.

`type FeeManager = ();` is **not** reported here. At the pinned SDK, `impl FeeManager for ()` returns `is_waived = false` and has an empty `handle_fee`, so fees are charged and then burned. That is reported separately, at warning, by [RTC006](RTC006.md).

## What it detects

Inside `impl xcm_executor::Config for ...` (or any `impl ...::Config for XcmConfig`):

- `type FeeManager = WaiveDeliveryFees;`
- `type FeeManager = XcmFeeManagerFromComponents<W, _>;` where `W` is `Everything`, a tuple containing `Everything`, or a type alias in the same file that resolves to one of those.

The `FeeManager` forms are not reported when the same impl sets both `type XcmSender = ();` and `type MessageExporter = ();`, because such an executor can never pay a delivery or export fee.

Anywhere in the runtime crate:

- `type PriceForSiblingDelivery`, `type PriceForParentDelivery` or `type PriceForChildParachainDelivery` (associated type or type alias) set to `()` or `NoPriceForMessageDelivery<..>`;
- `ParentAsUmp<_, _, P>` or `ChildParachainRouter<_, _, P>` where `P` is `()` or `NoPriceForMessageDelivery<..>`.

`WaivedLocations` aliases defined in another file are not resolved, so a cross-file alias of `Everything` is a false negative.

## Severity rationale

The default is **error**. Every matched form makes fees zero for every sender: there is no heuristic judgement involved. The SR Labs audits that reported free XCM delivery rated it High or Critical. No production runtime at the pinned SDK commit matches, so recall is guarded by `tests/fixtures/bad_rtc003.rs`, and the narrow `WaivedLocations` configurations of westend and asset-hub-westend are labeled FP guards.

The default comes from the rule itself, not from the bundled configuration. A user configuration that does not set `[runtime_config].severity` or `[rules.severity].RTC003` keeps it at error.

## Runtime scope

Same as all RTC rules; see [Runtime Configuration Rules](runtime-config.md).

## What should be avoided

```rust
impl xcm_executor::Config for XcmConfig {
    type XcmSender = XcmRouter;
    type FeeManager = WaiveDeliveryFees; // ❌ every fee waived
}

pub type WaivedLocations = Everything;
// ❌ XcmFeeManagerFromComponents<WaivedLocations, ..> waives every origin

impl cumulus_pallet_xcmp_queue::Config for Runtime {
    type PriceForSiblingDelivery = NoPriceForMessageDelivery<ParaId>; // ❌ free delivery
}
```

## Best practice

```rust
pub type WaivedLocations = (
    Equals<RootLocation>,
    RelayOrOtherSystemParachains<AllSiblingSystemParachains, Runtime>,
);

impl xcm_executor::Config for XcmConfig {
    type FeeManager = XcmFeeManagerFromComponents<
        WaivedLocations,
        SendXcmFeeToAccount<Self::AssetTransactor, TreasuryAccount>,
    >;
}

pub type PriceForSiblingParachainDelivery =
    ExponentialPrice<FeeAssetId, BaseDeliveryFee, TransactionByteFee, XcmpQueue>;
```
