# RTC003 - XCM Delivery Fees Burned or Waived

> **Severity:** Error · **Family:** runtime-config · **Engine:** source analysis (syn) · **Rule name:** `xcm-fees-waived`

## Description

XCM delivery fees are the congestion control for cross-chain messaging. Senders pay per message and per byte, and exponential pricing makes a flood progressively more expensive. Two configuration points switch this off:

- The executor's `FeeManager`. `impl FeeManager for ()` never waives a fee and does nothing with the fees it receives; the trait documents that this "silently burns the fees". `WaiveDeliveryFees` waives them outright. In both cases, no fee reaches an account that can use it to offset delivery costs.
- The delivery price of each router (`PriceForSiblingDelivery`, `PriceForParentDelivery`, `PriceForChildParachainDelivery`, or the third generic argument of `ParentAsUmp` / `ChildParachainRouter`). `()` and `NoPriceForMessageDelivery` make delivery free. Anyone can then fill the outbound XCMP/UMP/DMP queues for the price of a local transaction, delaying or dropping other users' messages and growing storage until the queues drain.

## What it detects

- `type FeeManager = ();` or `= WaiveDeliveryFees;` inside `impl xcm_executor::Config for ...` (or any `impl ...::Config for XcmConfig`), unless that impl also sets both `type XcmSender = ();` and `type MessageExporter = ();`, in which case no delivery or export fee can arise;
- `type PriceForSiblingDelivery`, `type PriceForParentDelivery` or `type PriceForChildParachainDelivery` (associated type or type alias) set to `()` or `NoPriceForMessageDelivery<..>`;
- `ParentAsUmp<_, _, P>` or `ChildParachainRouter<_, _, P>` where `P` is `()` or `NoPriceForMessageDelivery<..>`.

## Severity rationale

The default is **error**. All four SR Labs audits that reported this pattern rated it Critical or High. The matched forms have one meaning, so there is no heuristic judgement involved. On the pinned SDK corpus, the only production finding is a true positive in the parachain template, after the sender-less executor exemption.

## Runtime scope

Same as all RTC rules; see [Runtime Configuration Rules](runtime-config.md). `yet-another-parachain` (dev) uses all three forms on purpose and is reported only with `include_dev_runtimes = true`.

## What should be avoided

```rust
impl xcm_executor::Config for XcmConfig {
    type XcmSender = XcmRouter;
    type FeeManager = (); // ❌ fees silently burned
}

impl cumulus_pallet_xcmp_queue::Config for Runtime {
    type PriceForSiblingDelivery = NoPriceForMessageDelivery<ParaId>; // ❌ free delivery
}
```

## Best practice

```rust
impl xcm_executor::Config for XcmConfig {
    type FeeManager = XcmFeeManagerFromComponents<
        WaivedLocations,
        SendXcmFeeToAccount<Self::AssetTransactor, TreasuryAccount>,
    >;
}

pub type PriceForSiblingParachainDelivery =
    ExponentialPrice<FeeAssetId, BaseDeliveryFee, TransactionByteFee, XcmpQueue>;
```
