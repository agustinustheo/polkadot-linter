# RTC008 - Proxy Filter Fails Open

> **Severity:** Warning · **Family:** runtime-config · **Engine:** source analysis (syn) · **Rule name:** `proxy-filter-fails-open`

## Description

A restricted proxy type (`NonTransfer`, `Governance`, ...) is only as strong as its `InstanceFilter<RuntimeCall>` implementation. Two shapes of that implementation have let restricted proxies move the delegator's funds:

- **Deny-list filters.** `ProxyType::NonTransfer => !matches!(c, RuntimeCall::Balances { .. } | ..)` allows every pallet it does not name, including pallets added to the runtime later. Asset Hub Westend's `NonTransfer` denied `Balances` and `Assets` but not `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive` or `Indices::transfer`, all of which move value ([polkadot-sdk #12771](https://github.com/paritytech/polkadot-sdk/pull/12771), found by the Runtime Whitebox Fuzzer).
- **Wildcard supersets.** `is_superset` decides which proxy types a proxy may add or remove: a proxy can add or remove any proxy type it is a superset of. `(ProxyType::NonTransfer, _) => true` declares `NonTransfer` a superset of every other type, which is only sound if every other type's filter admits a subset of `NonTransfer`'s calls. On the fellowship Asset Hubs, `Collator` allowed `CollatorSelection` while `NonTransfer` did not, and on Collectives, `Secretary` allowed `SecretaryCollective`/`SecretarySalary`, so a `NonTransfer` proxy could escalate by adding those proxies ([polkadot-fellows/runtimes #1341](https://github.com/polkadot-fellows/runtimes/pull/1341)).

## What it detects

In each `impl InstanceFilter<RuntimeCall> for <ProxyType>` of a production runtime:

1. **`filter`**: an arm of the method's `match` statement whose body is `!matches!(c, ..)`. The rule lists every pallet the runtime's `construct_runtime!` / `#[runtime]` declares from a value-moving crate (`pallet_balances`, `pallet_assets` (every instance), `pallet_xcm`, `pallet_revive`, `pallet_contracts`, `pallet_asset_conversion`, `pallet_psm`, `pallet_uniques`, `pallet_nfts`, `pallet_nft_fractionalization`, `pallet_vesting`, `pallet_indices`, `orml_tokens`, `orml_xtokens`, `orml_currencies`) whose `RuntimeCall` variant the deny-list does not name. A pallet counts as denied when any of its calls is named (`RuntimeCall::Indices(pallet_indices::Call::transfer { .. })` denies `Indices`). If the runtime's pallets cannot be found, nothing is reported.
2. **`is_superset`**: an unguarded arm `(X, _) => true` where `X`'s own filter admits `Proxy::add_proxy` (so `X` can add the proxies it is a superset of) and some other proxy type `Y` (not matched by an earlier unguarded `(X, Y)` or `(_, Y)` arm) admits a call `X` does not. Filters are compared per `RuntimeCall` variant and per call: allow-lists (`matches!`) and deny-lists (`!matches!`), possibly in a block. A `Y` that allows a whole pallet is not covered by an `X` that allows only some of its calls. A deny-list `Y` escapes an allow-list `X`; two deny-lists, and filters of any other shape (including `true`), are not compared. The message names each proxy type `X` can add and one call it admits that `X` does not.

Allow-list filters, `ProxyType::Any => true`, and wildcards that every other filter really is a subset of (the Polkadot and Kusama relays' `NonTransfer`, which carves out `(NonTransfer, Auction) => false` first) are not reported.

## Limitations

- Filter patterns the rule cannot model precisely (`_`, bindings, guards, nested patterns) make the filter unknown, and unknown filters are never reported or compared.
- Runtimes whose `construct_runtime!` pallets cannot be resolved are skipped for deny-lists, e.g. the OpenZeppelin templates, whose `types.rs` defines the filter away from the runtime declaration.
- The `Proxy` pallet is recognised by its usual `RuntimeCall::Proxy` variant name; a superset whose filter names it differently is not reported.

## Runtime scope

Same as all RTC rules; see [Runtime Configuration Rules](runtime-config.md). Filters, `construct_runtime!` and proxy types must be in the runtime crate; filters are read per file.

## What should be avoided

```rust
impl InstanceFilter<RuntimeCall> for ProxyType {
    fn filter(&self, c: &RuntimeCall) -> bool {
        match self {
            ProxyType::Any => true,
            // ⚠️ fails open: ForeignAssets, PolkadotXcm, ... are allowed
            ProxyType::NonTransfer => !matches!(c, RuntimeCall::Balances { .. } | RuntimeCall::Assets { .. }),
            ProxyType::Collator => matches!(c, RuntimeCall::CollatorSelection { .. } | RuntimeCall::Utility { .. }),
        }
    }
    fn is_superset(&self, o: &Self) -> bool {
        match (self, o) {
            (x, y) if x == y => true,
            (ProxyType::Any, _) => true,
            (_, ProxyType::Any) => false,
            (ProxyType::NonTransfer, _) => true, // ⚠️ only sound if every filter ⊆ NonTransfer's
            _ => false,
        }
    }
}
```

## Best practice

Write restricted filters as allow-lists, and list superset relations explicitly (with a test that checks them against the filters, as #1341 added):

```rust
ProxyType::NonTransfer => matches!(c, RuntimeCall::System(..) | RuntimeCall::Session(..) | RuntimeCall::Utility(..)),
// ...
(ProxyType::NonTransfer, ProxyType::CancelProxy | ProxyType::Governance) => true,
```
