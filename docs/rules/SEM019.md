# SEM019 - Verifier trait method defaults to true

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `verifier-defaults-to-true` |

## What it finds

A trait method that verifies its input has a default body of `true`.

## Why it matters

Each implementer that does not override the method accepts every input.
`OpaqueKeys::ownership_proof_is_valid` defaulted to `true`, so
`pallet_session::set_keys` accepted session keys without proof of ownership.
[polkadot-sdk#1739](https://github.com/paritytech/polkadot-sdk/pull/1739) made
the method required.

## Example

```rust
// Bad:
pub trait OpaqueKeys {
    fn ownership_proof_is_valid(&self, _proof: &[u8]) -> bool {
        true
    }
}
```

```rust
// Good: no default.
pub trait OpaqueKeys {
    #[must_use]
    fn ownership_proof_is_valid(&self, owner: &[u8], proof: &[u8]) -> bool;
}
```

## How to fix

Remove the default body. If you must keep a default, return `false`.

## How it decides

The rule reports a trait method when all of these are true:

1. The default body is exactly `true` and the method returns `bool`.
2. It takes at least one argument besides `self`.
3. A word in its name is `verify`, `verified`, `valid`, `authorized` or
   `authorised`, or the name has both `ownership` and `proof`.
4. The name is not negated. No word is `invalid`, `unauthorized`,
   `unauthorised`, `validator`, `not` or `no`. No word starts with `deny`,
   `reject`, `needs` or `requires`.

## Limits

- The rule does not report implementations that return `true`. A no-op
  verifier is an explicit choice.
- It skips `#[cfg(test)]` code.
- Measured: 1 finding on polkadot-sdk before #1739, 0 after. 0 on current
  polkadot-sdk and polkadot-fellows/runtimes.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
