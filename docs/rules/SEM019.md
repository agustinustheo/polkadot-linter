# SEM019 - Verifier Trait Method Defaults to `true`

> **Severity:** Warning · **Family:** semantic · **Engine:** source analysis (syn) · **Rule name:** `verifier-defaults-to-true`

## Description

A trait method that verifies something and has a default body of `true` accepts every input for each implementer that does not override it. Nothing forces the implementer to notice. `sp_runtime::traits::OpaqueKeys::ownership_proof_is_valid` defaulted to `true`, and `impl_opaque_keys!` did not override it. `pallet_session::set_keys` therefore accepted any session keys without a proof of ownership. polkadot-sdk [#1739](https://github.com/paritytech/polkadot-sdk/pull/1739) ("frame-session: Introduce a proper proof of key ownership") made the method required.

## What it detects

A trait method that meets all of these conditions:

- it has a default body that is exactly `true`;
- it returns `bool`;
- it takes at least one argument besides `self`;
- one of its `_`-separated name words is `verify`, `verified`, `valid`, `authorized` or `authorised`, or its name has both `ownership` and `proof`;
- its name is not negated or inverted: no word is `invalid`, `unauthorized`, `unauthorised`, `validator`, `not` or `no`, and none starts with `deny`, `reject`, `needs` or `requires` (`proof_is_invalid`, `needs_proof` return `true` to reject).

Implementations (`impl Trait for T { fn verify(..) -> bool { true } }`) are not reported: an implementation that accepts everything is an explicit choice, such as a no-op `()` verifier. Methods without arguments (`fn is_valid(&self) -> bool { true }`) and `#[cfg(test)]` code are not reported either.

## What should be avoided

```rust
pub trait OpaqueKeys {
    fn ownership_proof_is_valid(&self, _proof: &[u8]) -> bool {
        true
    }
}
```

## Best practice

```rust
pub trait OpaqueKeys {
    #[must_use]
    fn ownership_proof_is_valid(&self, owner: &[u8], proof: &[u8]) -> bool;
}
```

If a default is needed, fail closed (`false`).
