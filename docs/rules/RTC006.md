# RTC006 - XCM fees burned

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| warning | on | syntax | `xcm-fees-burned` |

## What it finds

The XCM executor config sets `type FeeManager = ();`.

## Why it matters

On current SDKs, `impl FeeManager for ()` charges delivery and export fees and
then does nothing with them. The fees are burned. Senders still pay, so this is
not free messaging. But the treasury and collators get no revenue.

On older SDKs, `()` waived the fees. SR Labs reported that as Critical or High.
If your runtime uses such an SDK, set this rule to `error`.

## Example

```rust
// Bad
impl xcm_executor::Config for XcmConfig {
    type XcmSender = XcmRouter;
    type FeeManager = ();
}
```

```rust
// Good
impl xcm_executor::Config for XcmConfig {
    type FeeManager = XcmFeeManagerFromComponents<
        WaivedLocations,
        SendXcmFeeToAccount<Self::AssetTransactor, TreasuryAccount>,
    >;
}
```

## How to fix

Send the fees to an account, for example with `SendXcmFeeToAccount`.

## Limits

- It skips the impl when it also sets `XcmSender = ()` and
  `MessageExporter = ()`. That executor cannot send, so it collects no fee.
- Burning fees can be an intended policy. Suppress the finding with a reason in
  that case.
- Pinned SDK: 1 finding, the parachain template. It is correct.

Runtime scope: see [Runtime configuration rules](runtime-config.md).

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
