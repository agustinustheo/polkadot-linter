# SEC021 - Inverted verification guard

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | on | compiler (needs the driver) | `inverted-verification-guard` |

## What it finds

An `if verify(..) { reject }` guard. The code rejects the input when the
verifier returns `true`.

## Why it matters

The correct form is `if !verify(..) { reject }`. Without the `!`, the code still
compiles, but it rejects valid signatures and accepts invalid ones.
[GHSA-wwx5-gpgr-vxr7](https://github.com/advisories/GHSA-wwx5-gpgr-vxr7)
(CVE-2025-24800, critical) is this bug. `grandpa-verifier-primitives` 0.1.1
accepted false GRANDPA finality proofs. The tests passed only because the test
prover was also wrong. Version 0.1.2 fixed it
([hyperbridge@f0e85db](https://github.com/polytope-labs/hyperbridge/commit/f0e85db718f5165b06585a49b14a66f8ad643aea)).

## Example

```rust
// Bad: a valid signature is rejected.
if sp_io::crypto::ed25519_verify(&signature, &message, &public) {
    Err(anyhow!("invalid signature for precommit"))?
}

// Good:
if !sp_io::crypto::ed25519_verify(&signature, &message, &public) {
    Err(anyhow!("invalid signature for precommit"))?
}
```

## How to fix

Add the missing `!`, or use `ensure!(verify(..), ..)`.

## How it decides

The rule reports an `if` (also the `if` that `ensure!` expands to) when all
these conditions are true:

1. The condition is a verifier call that returns `bool`. An even number of `!`
   counts as no `!`. The verifier names are the same as in [SEC020](SEC020.md).
2. The `true` branch rejects directly. One of its own statements is
   `return Err(..)`, `return false` or `Err(..)?`, or its tail is `Err(..)`.
   A rejection inside a nested `if`, `match`, loop or closure does not count.
3. The `else` branch, if present, does not reject in the same way.

## Limits

- Not reported: negated verifiers, `ensure!(verify(..), ..)`, a conditional
  rejection, an `if`/`else` where both branches reject, and verifiers that
  return `Result<bool, _>` (SEC020 covers these).
- A verifier whose `true` means "reject" is a false positive. No such function
  exists in polkadot-sdk master or the fellows asset hubs.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
