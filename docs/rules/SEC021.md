# SEC021 - Inverted Verification Guard

> **Severity:** Error · **Family:** security · **Engine:** compiler-backed (rustc driver) · **Rule name:** `inverted-verification-guard`

## Description

A signature or proof check is usually written as `if !verify(..) { reject }`. Dropping the `!` keeps the code compiling and type-correct, but the verifier now rejects every valid signature and accepts every invalid one.

[GHSA-wwx5-gpgr-vxr7](https://github.com/advisories/GHSA-wwx5-gpgr-vxr7) (CVE-2025-24800, critical) is this exact bug. `grandpa-verifier-primitives` 0.1.1 (used by `ismp-grandpa` < 15.0.1) checked GRANDPA precommits with `if sp_io::crypto::ed25519_verify(..) { Err(..)? }`, so a malicious prover could convince the verifier that any header was final. The integration tests passed only because the prover was misconfigured too. Fixed in 0.1.2 by [polytope-labs/hyperbridge@f0e85db](https://github.com/polytope-labs/hyperbridge/commit/f0e85db718f5165b06585a49b14a66f8ad643aea).

## What it detects

An `if` (including the `if !cond { return Err(..) }` that `ensure!` expands to) where all of these hold:

- the condition, after removing an even number of `!`, is a call whose rustc-resolved return type is exactly `bool`;
- the callee's name contains `verify`, or is `is_valid`, `check_signature` or `validate_proof` (the SEC020 verifier set);
- the branch taken when the verifier returns `true` rejects by itself: one of its own statements is `return Err(..)`, `return false` or `Err(..)?`, or its tail is `Err(..)`. Rejections inside a nested `if`, `match`, loop or closure in that branch do not count, nor does an `Err(..)` that is only bound (`let _e = Err(..)`);
- the `else` branch, if any, does not reject the same way.

## What should be avoided

```rust
if sp_io::crypto::ed25519_verify(&signature, &message, &public) {
    Err(anyhow!("invalid signature for precommit in grandpa justification"))? // ❌ valid signatures rejected
}
```

## Best practice

```rust
if !sp_io::crypto::ed25519_verify(&signature, &message, &public) {
    Err(anyhow!("invalid signature for precommit in grandpa justification"))? // ✅
}
```

## Precision and scope

Not reported: negated verifiers, `ensure!(verify(..), ..)`, a `true` branch that returns `Ok` or rejects only conditionally, an `if`/`else` where both branches reject, and verifiers returning `Result<bool, _>` (SEC020 covers those). A function named `verify*` whose `true` really means "reject" would be reported. No such function exists in polkadot-sdk master or the fellows asset hubs.
