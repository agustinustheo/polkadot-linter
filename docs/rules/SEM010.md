# SEM010 - XOR operator used as exponentiation

| Severity | Default | Engine | Name |
| --- | --- | --- | --- |
| error | on | compiler (needs the driver) | `xor-as-exponentiation` |

## What it finds

An expression such as `10 ^ 12` or `2 ^ 64`. In Rust, `^` is bitwise XOR, not
a power.

## Why it matters

`10 ^ 12` is `6`, not one trillion. Token units, deposits and conversion
factors use powers of ten. One such constant makes every value that uses it
wrong, on every run. The code compiles, so only review can find it.

## Example

```rust
// Bad: this is 6.
pub const UNITS: Balance = 10 ^ 12;
```

```rust
// Good:
pub const UNITS: Balance = 10u128.pow(12);
pub const UNITS_LITERAL: Balance = 1_000_000_000_000;
```

## How to fix

Use `pow`, or write the literal with `_` separators. `pow` in a `const` is
computed at compile time.

## How it decides

Both operands are integer literals. The left operand is `2`, `10` or `100`.
The right operand is greater than `3`.

## Limits

It does not report XOR on variables or named constants.

## Configuration

No rule-specific settings. Use `[rules.enabled]` and `[rules.severity]`.
