# SEM010 - XOR Operator Mistaken for Exponentiation

> **Severity:** Error · **Family:** semantic · **Engine:** compiler-backed (rustc driver) · **Rule name:** `xor-as-exponentiation`

## Description

In Rust, `^` is the **bitwise XOR** operator, not exponentiation. Developers coming from Python, JavaScript (`**` aside), spreadsheets, or plain math notation regularly write `10 ^ 12` expecting one trillion and instead get `10 XOR 12 = 6`. Rust compiles this without a whisper of complaint: the expression is perfectly valid integer arithmetic.

In runtime code this mistake is catastrophic because powers of ten and two are exactly how token economics are written. Chain decimals (`10 ^ 12` plank per token), existential deposits, mint caps, and unit conversions all involve exponentiation of small bases. `10 ^ 12` evaluates to `6`, so a constant intended to be one trillion plank becomes six plank — an existential deposit of effectively zero, a mint of dust instead of treasury funding, or a conversion factor that misprices every balance by twelve orders of magnitude.

Unlike an overflow or a logic bug that needs specific inputs to trigger, this constant is wrong on every execution, and because it type-checks and runs, only a careful review of the numeric values catches it before funds are affected. The rule is severity Error for that reason: any match is almost certainly a genuine bug.

## What it detects

- A binary `^` expression on integer types where both operands are integer literals, the left operand (the "base") is `2`, `10`, or `100`, and the right operand (the "exponent") is greater than `3` — e.g. `10 ^ 12`, `2 ^ 64`, `100 ^ 4`. These shapes match how powers are written in token-unit math and are vanishingly unlikely to be intentional XOR.

## What should be avoided

```rust
// ❌ 10 ^ 12 is XOR: this is 6, not 1_000_000_000_000
pub const UNITS: Balance = 10 ^ 12;

parameter_types! {
    // Existential deposit intended as 0.01 token — actually 0 plank
    pub const ExistentialDeposit: Balance = UNITS / 100;
}
```

The chain launches with an existential deposit of zero, allowing unlimited dust accounts, and every value denominated in `UNITS` is wrong by twelve orders of magnitude.

## Best practice

```rust
// ✅ Option 1: integer pow
pub const UNITS: Balance = 10u128.pow(12);
```

```rust
// ✅ Option 2: an explicit literal (underscores make the magnitude reviewable)
pub const UNITS: Balance = 1_000_000_000_000;
```

Both make the intended magnitude explicit; `pow` is evaluated at compile time in const contexts, so there is no runtime cost.
