# Runtime Configuration Rules (RTC)

Runtime configuration rules inspect the *runtime crate* rather than individual pallets: `impl <pallet>::Config for Runtime` blocks, `construct_runtime!` / `#[frame_support::runtime]` declarations, `define_benchmarks!`, `parameter_types!` and the XCM executor configuration. Every rule encodes a misconfiguration that Security Research Labs reported in at least one public audit of a Polkadot SDK runtime ([srlabs/audit-reports](https://github.com/srlabs/audit-reports)).

| Rule | Title | Default severity | Engine |
| --- | --- | --- | --- |
| [`RTC001`](RTC001.md) | Placeholder WeightInfo in a Runtime Config | Warning | source (syn) |
| [`RTC002`](RTC002.md) | Pallet Missing from define_benchmarks! | Warning | source (syn) |
| [`RTC003`](RTC003.md) | XCM Fees Waived or Delivery Free | Error | source (syn) |
| [`RTC004`](RTC004.md) | Zero Existential or Storage Deposit | Warning | source (syn) |
| [`RTC005`](RTC005.md) | Insecure Collective-Flip Randomness in the Runtime | Warning | source (syn) |
| [`RTC006`](RTC006.md) | XCM Fees Burned | Warning | source (syn) |

## Which code is inspected

A file is inspected only when all of the following hold:

1. **It belongs to a runtime crate.** The nearest `Cargo.toml` above the file must declare a `[package]`. The rules follow its library target (`[lib] path`, default `src/lib.rs`) through `mod name;` declarations (including `#[path]` and `mod.rs` layouts), and the production modules they reach must declare **exactly one** runtime: `construct_runtime!`, a `#[frame_support::runtime]` module, a bare `#[runtime]` module containing `#[runtime::runtime]`/`#[runtime::pallet_index]`/`#[runtime::derive]` items, or `#[frame_construct_runtime]`. So `mod runtime; pub use runtime::*;` with the runtime declared in `src/runtime.rs` is recognised. Crates that declare several runtimes (XCM simulators, emulated networks, documentation cookbooks) are test or example harnesses and are skipped. Files under a virtual workspace manifest only (no package) are orphans and are skipped. Files that have no `Cargo.toml` above them at all fall back to checking the file itself.
2. **It is not test code.** `#[cfg(test)]`/`#[test]` items and items gated on the `runtime-benchmarks`, `try-runtime`, or `test-helpers` features are removed before analysis, including individual `construct_runtime!` entries. Files reached only through such a `mod` declaration (`#[cfg(test)] mod sandbox;`) are skipped. Paths inside the crate with a `test`, `tests`, `mock`, `mocks`, or `benches` name token (split on `-`, `_` and `.`, so `mock.rs`, `xcm_mock/` and `integration-tests/` match but `testnet.rs` does not) are skipped, as are benchmark files. Files the module walk cannot reach (for example modules generated by macros) are still inspected.
3. **It is not a test runtime.** A runtime whose package name or crate directory has a name token in `test_runtime_tokens` (default `test`, `tests`, `mock`, `mocks`) is always skipped: `polkadot-test-runtime` and `cumulus-test-runtime` are, `mychain-testnet-runtime` and `contest-runtime` are not. Set `test_runtime_tokens = []` to lint them all.
4. **It is not a dev runtime, unless you opt in.** Packages listed in `[runtime_config].dev_runtime_packages` are skipped unless `include_dev_runtimes = true`. The default list is `kitchensink-runtime`, `penpal-runtime`, `rococo-parachain-runtime`, `yet-another-parachain-runtime`, `pallet-staking-async-parachain-runtime` and `pallet-staking-async-rc-runtime`: runtimes that exist to exercise node, emulator, or pallet features and that deliberately use placeholder weights, zero deposits, and free XCM delivery.

Everything else is treated as production-intended. That deliberately includes the SDK **templates**: SR Labs' OpenZeppelin audits show that template misconfigurations become production misconfigurations when teams fork them. It also includes the Westend/Rococo relay chains and the system parachains, which are live test networks.

## Configuration

```toml
[rules.severity]
RTC006 = "error" # e.g. on an SDK where `impl FeeManager for ()` waives fees

[runtime_config]
# severity = "warning"  # optional; overrides every RTC rule's own default
include_dev_runtimes = false
dev_runtime_packages = ["kitchensink-runtime", "penpal-runtime"]
test_runtime_tokens = ["test", "tests", "mock", "mocks"]
unit_weight_info_allowlist = ["pallet_babe", "pallet_beefy", "pallet_grandpa"]
flag_substrate_weight = false
substrate_weight_severity = "advisory"
```

## Pinned SDK corpus

`scripts/check-source-runtime-corpus.sh` scans `polkadot/runtime`, `cumulus/parachains/runtimes`, `templates`, `substrate/bin/node/runtime`, `cumulus/test` and `polkadot/xcm` at the pinned SDK commit, compares per-root counts with `benchmarks/polkadot-sdk-source-runtime-baseline.tsv`, and checks every TP/FP label in `benchmarks/labels/RTC.tsv`. Every reported finding must be labeled.

Label evidence follows the shared `oracle:<name>` / `manual` convention, plus one extension: FP rows whose evidence is `scope:<reason>` (`scope:dev_runtime_packages`, `scope:test_runtime_tokens`, `scope:runtime-crate-detection`, `scope:cfg-test`) assert that the location is out of scope for the RTC rules. They are not evidence that the pattern is benign: penpal's zero deposits, for example, are real. The checker treats them exactly like FP rows (the location must not be reported) and counts them separately.
